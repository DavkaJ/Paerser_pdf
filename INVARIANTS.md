# Инварианты проекта (обязательны для любого изменения)

Эти правила не обсуждаются в каждом промпте — они держат корпус в измеримом,
воспроизводимом состоянии. Нарушение любого — повод остановиться, а не «пока так».

## 1. Схема выходного JSON — только аддитивно
Новые поля добавлять можно; существующие (`metadata`, `sections[].number/title/level/
text/children`, `tables[].page/number/caption/raw_text/bbox`, `excluded`,
`stats.coverage_percent`, …) сохраняют имя, тип и семантику. Downstream-потребители
(коллеги с `outout_pass/`) не должны сломаться. Новые ключи — В КОНЦЕ объектов, чтобы
диффы читались.

## 2. Разрушающие тесты — ТОЛЬКО по изолированным путям
Любой тест, который пишет/удаляет выход, портит базу или ломает запись, ОБЯЗАН идти по
изолированным путям и НИКОГДА по боевым:
- `CR_OUTOUT` / `CR_REPORT` / `CR_OCR_CACHE` — переопределить на temp перед запуском
  batch_report/release в тесте;
- сбой записи, мутацию пинов, crash — воспроизводить **in-process через monkeypatch**
  (`batch_report.work` / `compute_integrity` / `publish`), а НЕ через env-хук в боевом
  воркере. **Запрещено** держать в продакшен-коде хуки вида `CR_TEST_*`, которые при
  утечке переменной окружения повредят корпус. (Урок: хуки `CR_TEST_FAIL_WRITE` /
  `CR_TEST_TOUCH_PINS` были удалены — второй ДОПИСЫВАЛ в реальную `ocr_pins.json`.)
- прогон batch без `CR_OUTOUT`/`CR_REPORT` перезаписывает боевые `outout/` и
  `_corpus/report.json` — для тестов это недопустимо.

## 3. Все записи отчётов/выходов — атомарны
`report.json`, каждый `outout/*.json`, run_manifest, кэши пишутся через
`JsonWriter._atomic_dump` (temp + fsync + os.replace). Прерывание не оставляет
обрыв/торн-JSON. Обычный `json.dump(open(path,"w"))` в продуктовом пути запрещён.

## 4. Пины — immutable вход прогона
`crparser/data/ocr_pins.json` не изменяется во время прогона (sha до == sha после —
gate-критерий). Накопленные пары уходят в `_corpus/pins_proposed_*.json` на ревью,
а не в базу.

## 5. OCR — объявленное предусловие, не удача среды
Путь Tesseract — только из `TESSERACT_CMD`/`TESSERACT_PATH`/PATH (без угадывания
домашних каталогов). Полный прогон корпуса идёт с `--require-ocr` (по умолчанию);
недоступный OCR -> `run_integrity_ok=False`, exit 2, публикации нет.

## 6. Ни один не-PASS не лежит в отгружаемой директории
`candidate_release/` (до аттестации на gold set — не `release/`) содержит только PASS,
вырезанные по `training_contract.json`. `UNVERIFIABLE_OCR` не попадает туда ни при каком
статусе, пока промпт 16 не устранит двойное чтение PDF. `--current` (незамороженное
состояние) требует `--i-know-this-is-unfrozen` и помечается `not_for_distribution`.

## 7. Baseline и дрейф
`_corpus/baseline_manifest.json` (промпт 01) — ЗАМОРОЖЕННАЯ точка отсчёта. Любой
output-меняющий промпт прикладывает дельту `manifest --verify` и объясняет её. Baseline
пересниматься должен только по явному решению, с записью причины.

## 8. Пороги — именованные константы
Каждый порог — константа с комментарием, на каком замере получена. Пороги гейтов 04 —
triage (не gold set): файл, прошедший их, — КАНДИДАТ, не аттестованный документ, пока не
выполнен промпт 14.

## 9. Коммиты — по существу
Без упоминания AI/Claude, без `Co-Authored-By`. Один осмысленный коммит на промпт.
Не коммитить на красном регресс-наборе (`pytest tests/`).
