# Применение подтверждённых правок к тексту корпуса (п.5а) — вход готов, применение отложено

## Статус
Вход собран и провенансирован. САМО применение к тексту НЕ сделано в этом заходе НАМЕРЕННО:
правка текста корпуса требует движкового инжекта + перепарса + аудита каждой замены против
источника (дисциплина I30 и «аудит auto-set до заявления о нуле порчи»). Рушить парсер впопыхах
под лимит бюджета — хуже, чем оставить готовый, воспроизводимый вход. «Ничего молча в текст».

## Готовые входы (закоммичены)
- `verify_queue/_verified_corrections.json` — **72 формы** `source→corrected` к применению, провенанс:
  - `human_verified_5a` (53) — правки человека из ls_export, размножить на ВСЕ вхождения формы.
  - `reverified_*` (19) — из пере-сверки 72 крит.: homoglyph-norm TNM (12), физио (6), crop J01XX (1).
  - конфликт `JO1XХ`: побеждает crop-значение `J01XX` (полностью латинское), а не человеческое
    `J01XХ` с остаточной кир. Х.
- `verify_queue/_requeue_critical.json` — **3 крит. ATC** (СО2АВО2→C02AB02, СО2АВО1→C02AB01,
  СО8САО2→C08CA02), что НИ человек, ни LLM не подтвердили верно → назад человеку, НЕ в текст.

## Точка инжекта (движок) — конкретно
`crparser/engine/latinrecovery.py`:
1. `__init__`: загрузить карту `verify_queue/_verified_corrections.json` в `self._verified` (dict).
2. `recover()` после сборки карт (строка ~645, где создаются `self._g/_tnm/_whole`): наложить
   поверх `self._g` записи для каждой формы из `self._verified`:
   `self._g[form] = _mkrec(form, corrected, method="human_verified", rule=provenance, conf=..,
   kind=.., decision="auto")`. Контракт `_apply` (строка 1177+) уже применяет ТОЛЬКО `decision=="auto"`
   к тексту и пишет провенанс через `_emit` (`applied=True`). То есть инжект = один overlay-цикл.
   ВАЖНО: `source="human_verified"` в провенансе, чтобы отличать от механических каналов.

## Обязательный порядок исполнения (следующий заход / серверные модели)
1. Инжект (выше) + `source=human_verified` в провенанс.
2. Перепарс ЗАТРОНУТЫХ документов С OCR (fail-closed гейт уже есть) — не всего корпуса; список
   docs берётся из `_resolved_human`/`_resolved_final` (напр. КР10_5 с ВАР1→BAP1).
3. **АУДИТ КАЖДОЙ применённой замены против источника**: для каждой формы, где `applied=True`,
   сверить, что в новом тексте нет исходной порченой формы и есть corrected; выборочно — по кропу.
   Не заявлять «0 порчи» без этого прохода (память: два ревью ловили молчаливую порчу).
4. Тест исполняет путь (I30): перепарс КР10_5 с OCR, assert `BAP1` в тексте и провенанс
   `applied=True, source=human_verified`; `ВАР1` отсутствует. Добавить в `tests/test_latin_apply_contract.py`.
5. Только после зелёного аудита+теста — регенерация всего латинского слоя и обновление report.

## Почему не применил строковой заменой по outout_latin (важно)
1409/2857 форм не находятся в латинизированном тексте дословно (порча != латинизированный вывод),
плюс off-pipeline замена теряет провенанс и гейты. Правильно — через движок при перепарсе.
