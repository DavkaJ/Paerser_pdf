# Font-repair pilot (промпт 13, ЭТАП 1 + 1-bis) — ОТЧЁТ и РЕШЕНИЕ

## Механизм (уровень ШРИФТА, по совету заказчика) — реализован, `crparser/engine/fontrepair.py`

Для каждого встроенного субсета ОДИН РАЗ: хеш контура каждого глифа (с декомпозицией
композитов) → сопоставление с эталонами (times/timesbd/timesi/timesbi/arial*, 7219 хешей,
336 гомографов) → карта `GID → {истинные символы}`. Сверка с картой `/ToUnicode` шрифта →
**доля согласия**. Низкая → шрифт битый, применить контурную карту; высокая → здоров, НЕ трогать.

## Метрики (ЭТАП 1-bis)

- **false_substitution = 0.000000** (КР1000_1, здоров: 0 изменённых символов из 144 078).
  **ГЛАВНАЯ метрика МЕТ, притом ПО ПОСТРОЕНИЮ:** здоровые шрифты (agreement 0.97–1.00 замер)
  не проходят гейт `corrupt` → декодер возвращает /ToUnicode без изменений → испортить
  здоровый текст структурно НЕЛЬЗЯ. Разрыв agreement огромен: КР1000_1 ≥0.97, КР1_4 ≤0.01.
- **Механизм ДОКАЗАН на изолированных спанах:** битый шрифт КР1_4 (agreement 0.000) —
  контур восстанавливает `T1a`, `N0`, `T2`, `II`, `T4` ТОЧНО (стр.11 TNM-стадирование).
- **recall (полный конвейер) = 2/17 ≈ 0.12** по пин-списку аудита §4.1/§4.2. < 0.50.

## Почему recall низкий (три независимые причины)

1. **Гомографы доминируют в пин-списке.** `IA/IB/IVA/IVB` (I↔1), `M0` (O↔0), `Gx` (G↔О),
   `Ш`=III (ОДИН глиф = ТРИ символа) — контур один, символов несколько. Разрешение —
   только шаблоном сущности (TNM/МКБ/ATC), это уже не «контур решает».
2. **Часть пинов — в OCR-территории, не в теле нативного слоя.** `Barcelona`/`BCLC`/
   `Hepatitis` — в ЯЧЕЙКАХ Таблицы 1 (over-capture кропа), которые уже чинит OCR (09,
   raw_text из IR). Их нет в теле как класс-A спанов font-repair.
3. **span→субсет маршрутизация неоднозначна.** `get_texttrace` даёт ИМЯ шрифта без
   xref/префикса; при нескольких субсетах «TimesNewRomanPSMT» на странице GID→субсет не
   определить. Две стратегии (corrupt-bonus, строгое покрытие) дали одинаковые 2/17.

## РЕШЕНИЕ (Р2, самостоятельно): **NO-GO как СТАНДАЛОН-канал** (валидный исход, не провал)

`recall < 0.50 → NO-GO`. Font-repair НЕ становится основным детерминированным каналом
класса A: пин-список аудита в основном гомографы и OCR-территория, где контур сам по себе
не даёт ответа. **НО:**
- `false_substitution ≤ 0.001` выполнен АБСОЛЮТНО (=0) — инструмент БЕЗОПАСЕН;
- механизм и гейт-по-согласию — рабочие и переиспользуемые;
- истинное место font-repair — **второе мнение / гомограф-предфильтр в РОУТЕРЕ (16)** рядом
  с OCR (safe: не трогает здоровое; disambiguation: контур сужает гомографы, OCR/шаблон
  добивает), а НЕ standalone-подмена.

`crparser/engine/fontrepair.py` оставлен как проверенный фундамент (в конвейер НЕ включён →
0 влияния на вывод, регресс не затронут). Класс B (`стетогепатитный`, пропавшие буквы) —
вне зоны, как и оговорено. **Идём к 13b.**
