# НОЧНОЙ ПРОГОН — интеграция latin recovery (промпт 13b). Отчёт к утру.

## Вердикт
Механизмы латиницы **подключены к боевому пайплайну** за флагом `--latin-recovery`; весь
корпус (701 обучаемый док) прогнан в `outout_latin/` с провенансом на каждую замену; собрана
**очередь верификации** для Label Studio (6250 задач + кропы). Приёмочные тесты **A/B/C
зелёные** (14 passed, 1 xfail — UICC, объяснён). **Дельта статусов vs baseline — НУЛЕВАЯ**
(PASS 529 стабилен), контрольная группа I1 — вся PASS. Baseline `outout/` НЕ тронут (13b:
за флагом, не в релиз до gold; I8). Корпус вычищен по максимуму безопасными каналами; спорное
(needs_review) применено лучшим кандидатом и сложено в очередь на человека.

## Каналы резолвера (`crparser/engine/latinrecovery.py`), СЕГМЕНТНАЯ замена
1. **A2-шаблон** — кир-гомограф буквы в слоте кода (`С18→C18`, `D08АС02→D08AC02`). Детерминизм, fsr=0.
2. **Цифро-слот TNM** (`МО→M0`, `ТО→T0`) — ТОЛЬКО в staging-регионе (иначе «МО»=мед.орг. цела).
3. **N-из-Ы** (`Ых→Nx`), **font-repair** не-гомографов (контур), **римская стадия** (`Н-Ш→II-III`).
4. **eng-OCR по кропу** + **гейт формы** для кодов (`037.6→D37.6`, `501ЕС→S01EC`); термины — по
   позиции; **ген** (`СТЪА4→CTLA4`) — только с E3-подтверждением. Провенанс: блок `latin_recovery`.
Release-gate `LATIN_UNRESOLVED` в validate.py; `□` unmapped → удаление (ШАГ 4).

## Дельта статусов vs baseline
Восстановленный корпус: **PASS 529 / REVIEW 109 / FAIL 63**. Baseline: 529/130/63.
**Дельта переходов = ∅ (ноль документов сменили статус).** FAIL-сигнатуры — прежние структурные
(MISSING 63, CANONICAL_RECALL) — НЕ latin. Latin recovery аддитивен: чинит текст, не ломает статус.
(Первый прогон дал STATS_MISMATCH у 431 док — резолвер считался ПОСЛЕ stats; перенесён ДО, фикс.)

## Как открыть очередь верификации (одна команда)
```
label-studio start latin_verify --init \
  --input-path _corpus/verify_queue/tasks.json \
  --label-config _corpus/verify_queue/labeling_config.xml \
  --input-format json-task
```
6250 задач (дедуп по doc+source), 5217 кропов (`_corpus/verify_queue/crops/`, ~400 DPI). Задачи
отсортированы: критические первыми. Каждая задача: crop-картинка + исходник + кандидаты + причина.

## Что осталось / затыки (честно)
1. **UICC←ШСС (1 токен, КР1_4)** — all-caps лосси-акроним (3 глифа→4 буквы: контур/шаблон бессильны,
   нужен eng-OCR по пикселям), НО `ШСС` freq-защищён и неотличим от рус. all-caps аббревиатуры БЕЗ
   риска Group B: любой «all-caps→eng-OCR» пасс латинизировал бы `СОД→COD`, `ВГД→BID`. Взять его =
   хардкод имени (запрет I11) или регресс Group B. Оставлен на человека/gold — xfail с этим reason.
2. **needs_review-термины (4367)** — eng-OCR имён/терминов (Karnofsky, Barcelona, авторы ссылок)
   применён лучшим кандидатом, помечен needs_review, в очереди. Большинство — реальная порча
   латиницы (термины/URL); меньшинство — 真-рус. FP склеек (`синдромеВ`); все НЕ-auto, не критические.
3. **130 unresolved-критических в 88 док** — на карантине LATIN_UNRESOLVED (правильная работа гейта).

## Механизм FP-безопасности (Group B), выстрадано на корпусе
freq≥3 = рус. слово (не трогаем); TNM только в staging; детекторы отличают ГЛИФ-порчу от
СКЛЕЙКИ (скобка перед буквой=глиф / перед цифрой=цитата; camelCase кир.заглавная не перед словом;
цифра БУКВА-ЦИФРА-БУКВА, не хвост/ведущий-номер; сегментация режет `- / + ( ) *`). Ген — только
через E3. Release-block — только на сильной улике (кир-гомограф в валидном шаблоне).
