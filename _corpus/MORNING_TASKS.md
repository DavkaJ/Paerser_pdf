# Утренние задачи (модели подняты) — для Claude Code

Ночью человек размечает 73 критических в Label Studio (проект `latin_verify`).
**НЕ пересоздавать проект. Перед любой регенерацией корпуса — ЭКСПОРТ аннотаций из LS.**
Все правки — за коммит, с провенансом, тест исполняет путь (перепарс с OCR). Нич��го молча в текст.

## 1. Арбитр mixcase-латиницы (Cowork-ревью 3, отложено на утро)
mixcase-гейт защищает русские аббревиатуры (иПТГ/иФНО/мКРРПЖ — ~975 форм), но вместе с ними
МОЛЧА оставляет битую латиницу (`СЫатусИа`=Chlamydia, `сЬгошс`). Требование заказчика: ни одной
нераспознанной латиницы молча в тексте.
- Собрать дедуплицированный набор mixcase-all-cyr токенов в тексте, НЕ входящих в очередь.
- **LLM-арбитр** классифицирует каждую форму: «русская аббревиатура / битое латинское слово».
- Битые латинские → авто-фикс при высокой уверенности (провенанс), иначе needs_review → в очередь.
- Русские аббревиатуры не трогать.
- Замерить/доложить: сколько битых нашлось, сколько в авто, сколько в очередь.
- Промпт арбитра калибровать осторожно (не зачислить редкую рус.аббревиатуру в «латиницу»).

## 2. Фильтр URL/ссылок из очереди (замерено: 411 задач в 50 док.)
Детектор выхватывает фрагменты битых URL (`з1ап`=stan из `https://rosoncoweb.ru/standards/...`) —
для человека это бесполезный шум. Отфильтровать спаны в URL-контексте в `_noise.jsonl`, не человеку.
- Признаки контекста: `http`, `://`, `ЬЦрз/Ьйрз` (искаж. https), `.ru/`/`.ги/`, `www`, `.pdf`,
  доменные паттерны, `doi`.
- После фильтра доложить новый размер очереди (ожидание ~2826 вместо 3237).

## 3. (Рекомендация) общий result-validity гейт — корневой фикс всего семейства
Четыре класса порчи (цитаты, предлоги, mixcase-мусор, URL) — один паттерн: канал считает легит-
источник порчей, а гейт применения не проверяет валидность результата. Общий гейт на ВСЕ
auto-каналы: не применять авто-замену, если результат не валиден (не реальное англ/лат слово,
не валидная форма сущности → needs_review). Закрыло бы класс целиком, а не по одному.

## 4. Не забыть про «СЫатусИа»-подобные (из ревью 3)
Часть битой латиницы с случайным смешанным регистром сейчас не восстанавливается И не в очереди.
Пункт 1 (арбитр) должен их подхватить. Проверить, что после него: 0 «битая латиница молча в тексте».

## 5. Использовать РАЗМЕЧЕННЫЕ ПАРЫ (экспорт из Label Studio) — сокращает будущую ручную работу
Ночная разметка человека — не только фикс своих спанов, а обучающий сигнал. Экспортировать
аннотации из LS (JSON) и:
- **(а) Размножение по форме.** Подтверждённую правку (`source_text`→`corrected_text`, decision=
  accept/enter_own) применить ко ВСЕМ вхождениям этой формы в корпусе (дедуп по форме), с
  провенансом `human_verified`. Одно решение → десятки исправлений.
- **(б) Белый список / фильтры из негативов.** decision=source_ok → добавить форму в whitelist
  (детектор перестаёт флагировать: `ЭоЭ`, `Т2`, …). entity_kind_fix=not_entity → класс в фильтр
  (Vol.NN, URL, ссылки). Это чистит СЛЕДУЮЩУЮ очередь.
- **(в) Пер-документная карта подстановок.** Из пар «битое→правильное» вывести glyph-map того
  документа/семейства шрифтов (подстановка внутри одного PDF устойчива) и авто-раскодировать
  ОСТАЛЬНЫЕ битые слова того же документа — с проверкой по словарю (англ/лат). НЕ глобально:
  карта пер-шрифтовая. Неуверенное → needs_review, не в текст.
- **(г) Gold-калибровка каналов.** На размеченном подмножестве измерить точность каждого
  auto-канала (a2_template/ocr_eng/self-repair/homoglyph) — решить, что пускать в авто, что в
  очередь. Это gold set промпта 14, собранный из разметки бесплатно.
- **(д) Few-shot для арбитра (п.1).** Подтверждённые примеры (иПТГ=рус, СЫатусИа=Chlamydia) —
  в промпт арбитра; разметка же валидирует его вывод.
Цель — самоусиливающийся цикл: разметка → карта+фильтры → авто-декод большей части → человеку
только хвост. Приоритет: (а) и (б) дёшевы и без моделей, делать сразу после экспорта.

## 6. LLM-предсказания на ВСЮ очередь (пред-заполнить подсказки для человека)
Инсайт: точность приходит от КОНТЕКСТА документа (LLM видит, что «Herpes simplex virus» стоит
рядом корректно; что `Vol.54` — цитата; что `з1ап` внутри URL). Механические каналы контекст
не видят — отсюда кандидаты вроде «Herpes C simplex virus». Прогнать LLM по всей очереди с
контекстом и пред-заполнить подсказки, чтобы человек ПОДТВЕРЖДАЛ, а не решал с нуля.

Дизайн (безопасный, по инвариантам I28-I30):
- **Вход на задачу:** source_text + окно контекста из `outout_latin` (±~200 симв. вокруг спана) +
  кроп (если есть) + существующие кандидаты + entity_kind + is_critical.
- **Выход LLM:** predicted_text, predicted_entity_kind, action ∈ {fix, source_ok, not_entity,
  url_ref, illegible, need_expert}, confidence, короткая причина.
- **Записать в задачу поле `llm_suggestion`** (показывать человеку как пред-заполненное). В ТЕКСТ
  КОРПУСА НЕ применять — только человек подтверждает. Провенанс.
- **Критические (коды/гены/дозы) — человек подтверждает ВСЕГДА.** LLM не выдумывает ICD-код из
  контекста; для крит. его вывод — подсказка, не истина.
- **Гейты те же:** result-validity (не предлагать несуществующие формы, напр. «Herpes C simplex
  virus»), Group-B (не латинизировать валидное русское), URL/ссылки → action=url_ref.
- **СНАЧАЛА калибровка:** прогнать LLM на ночных размеченных человеком задачах (73 крит. + др.),
  сравнить agreement. ≥95% → доверять предсказаниям на остальных; <95% → чинить промпт до масштаба.
- Отсортировать: LLM-высокая-уверенность-некритические → пачки «быстрый accept»; критические и
  LLM-низкая-уверенность → полный ручной разбор.
Payoff: человек листает подтверждения, а с нуля решает только спорное/критическое.

## 7. Реклассификация критичности (обратная связь заказчика при разметке)
Наблюдение: клинически значимые аббревиатуры лежат в НЕкритических (317 аббревиатуро-подобных).
Текущий is_critical = только icd/atc/tnm/доза/ген — не ловит патогены, стадии, типы клеток.
- **Поднять в критические/приоритет:** патогены (ЦМВ=CMV, ВПГ/HSV, ВЭБ/EBV), типы клеток
  (ЫК=NK), стадии заболевания (kind=stage: Ш-1У→III-IV, Н-Ш→II-III), классы препаратов.
- **Оставить/отфильтровать как НЕкритические:** названия организаций/баз в ссылках
  (UICC/ШСС, RUSSCO/1Ш88СО, MEDLINE/МЕОЫЫЕ, ESPEN), англ. слова и URL в библиографии.
- НЕ делать «все аббревиатуры критическими» — затянет библиографический мусор.
- Способ: расширить критерий критичности по entity_kind (+pathogen +stage +cell +drug_class),
  ЛИБО добавить средний приоритет между critical и обычными term. Пересортировать очередь.

## ОПЕРАЦИОННОЕ ОГРАНИЧЕНИЕ (обязательно) — не выжигать лимиты
- **МАКСИМУМ 4 агента.** В прошлый раз ultracode создал 169 агентов и выжег 5-часовой лимит за
  десятки минут, работа осталась не сделана. Больше так не делать.
- НЕ использовать крупные веерные ultracode-прогоны (агент-на-задачу). Большие объёмы
  (пере-сверка 72 критических, предсказания по остатку ~2800) обрабатывать **последовательными
  пачками внутри не более 4 агентов**, а не десятками/сотнями параллельных.
- Если задача не влезает в 4 агента за один заход — сделать частично, зафиксировать прогресс и
  остановиться, а не наращивать число агентов.
- Модели: пока Опус в текущем режиме. С завтрашнего дня — переход на серверные решения (внутренние
  модели), тогда лимиты Опуса перестанут быть узким местом.
