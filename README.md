# crparser — единый парсер клинических рекомендаций (КР) → JSON



PDF клинической рекомендации → структурированный JSON (метаданные, разделы с
иерархией, таблицы, excluded-блоки, статистика покрытия).

## Архитектура

Три физически разделённых слоя. Движок работает **только** через абстракцию
`DocumentProfile` и не знает, КР перед ним или иной документ.

```
crparser/
  engine/                 # СЛОЙ 1 — общая механика, не знает тип документа
    models.py             #   датаклассы-контракт: Line, Heading, Table, Section, …
    pdf_reader.py         #   PdfReader — чтение PDF с layout (PyMuPDF): шрифт, bbox
    tables.py             #   TableExtractor — таблицы по bbox (pdfplumber) + фильтр + вычитание
    segmenter.py          #   Segmenter — конечный автомат: отсечение ToC, нарезка, иерархия
    stats.py              #   StatsCalculator — покрытие/счётчики
    jsonio.py             #   JsonWriter — сборка и запись JSON по схеме
    parser.py             #   DocumentParser — оркестратор (работает через профиль)
  profiles/               # СЛОЙ 2 — специфика типа документа (ООП)
    base.py               #   DocumentProfile(ABC): classify_heading / extract_metadata /
                          #                          excluded_regions / named_section_id (+ хуки)
    registry.py           #   ClinicalRegistry — загрузка Excel-реестра, lookup по ID
    clinical.py           #   ClinicalRecommendationProfile(DocumentProfile) — профиль КР
  interface/              # СЛОЙ 3 — точки запуска
    cli.py                #   CLI
run.py                    # тонкий вход в CLI
batch_report.py           # утилита пакетной проверки качества (валидация)
```
.

### Как добавить новый тип документа

1. Создать `crparser/profiles/<name>.py` с классом `MyProfile(DocumentProfile)`,
   реализовав 4 абстрактных метода (и при необходимости хуки склейки/инлайна).
2. Зарегистрировать его в `crparser/profiles/__init__.py` (`_PROFILES`).
3. Запускать: `python run.py <pdf> --profile <name>`.

Движок менять не нужно. (Сейчас реализован один профиль — `cr`.)

## Установка

```
pip install PyMuPDF pdfplumber openpyxl
```

## Запуск (CLI)

```
python run.py <pdf-или-папка> --profile cr --registry <excel> --out <папка>
```

| параметр       | назначение                                                       |
|----------------|------------------------------------------------------------------|
| `input`        | один PDF **или** папка с PDF (обрабатываются все `*.pdf` в цикле) |
| `--profile`    | профиль документа (по умолчанию `cr`)                            |
| `--registry`   | путь к Excel-реестру КР (источник метаданных по ID)              |
| `--out`        | папка для JSON (по умолчанию — рядом с PDF)                       |
| `--quiet`      | не печатать сводку по файлам                                      |

Примеры:

```
python run.py data\текст_после_чистки\КР100_2.pdf --profile cr --registry Список_утвержденных_клинических_рекомендаций_2.xlsx --out out
python run.py data\текст_после_чистки --profile cr --registry Список_утвержденных_клинических_рекомендаций_2.xlsx --out out
```

## Запуск (веб-UI, опционально)

Простой локальный интерфейс (Flask) — тот же движок и профили:

```
pip install Flask
python -m crparser.interface.web      # затем открыть http://127.0.0.1:5000
```

Поля: путь к PDF/папке, выбор профиля, путь к реестру, папка вывода. Показывает
сводку по каждому файлу. Локальный инструмент (127.0.0.1), пути — на этой машине.

## Что объединено из двух парсеров

- **Заголовки по шрифту (размер/жирность) + структура номера**, со склейкой
  многострочных и **пословно разбитых** заголовков; канонический контроль
  номер↔название для разделов верхнего уровня КР. Распознаются все формы
  разделителя «номер↔заголовок»: «1.2 Этиология», «1.2. Этиология» и
  «1.2.Этиология» (точка вплотную, без пробела) — граница определяется первой
  буквой заголовка, а не обязательным пробелом.
- **Отсечение оглавления (ToC) до нарезки**: кластер точек-лидеров + конечный
  автомат режимов (front/section/refs/appendices), маркер-разрывы для ToC без точек.
- **Таблицы по bbox (pdfplumber)** с фильтром ложных детекций (bbox в пределах
  страницы, ≥2×2, ≥4 непустых ячейки) и **вычитанием** текста таблицы из разделов.
- **Метаданные из Excel-реестра по ID** (надёжно даже на сканах), с **fallback**
  на парсинг титула и `warnings` в обоих случаях.
- **Коды МКБ списком** с нормализацией кириллических двойников латинских (С→C, Е→E).


## Схема выходного JSON

```jsonc
{
  "metadata": { "source_file", "document_type", "title", "id", "year",
                "age_group", "mkb_codes": [...], /* + поля реестра */ },
  "sections": [ { "number", "title", "level", "text",
                  "children": [ /* рекурсивно */ ] } ],
  "tables":   [ { "page", "number", "caption", "raw_text", "bbox": [...] } ],
  "excluded": { "front_matter", "toc", "references", "appendices", "other" },
  "stats":    { "total_chars", "total_words", "sections_found", "tables_found",
                "included_chars", "excluded_chars", "accounted_chars",
                "coverage_percent" },
  "warnings": [ ... ]
}
```

## Проверка качества (Этап 2)

`batch_report.py` прогоняет пакет и печатает агрегаты (покрытие, доля метаданных из
реестра, наличие раздела 4, ToC-утечки, таблицы, ошибки):

```
python batch_report.py 180 10 spread
```

На выборке 180 КР по всему корпусу: 100% без ошибок, метаданные/название/МКБ —
100% (из реестра), ToC-утечек 0, медианное покрытие ~99.9%. Файлы с покрытием 0% —
сканы без текстового слоя (определяются и помечаются warning); метаданные для них
всё равно берутся из реестра.

### Структурная самопроверка против оригинала — `validate.py`

`validate.py` сверяет вывод парсера с самим PDF, используя **«Оглавление»
документа как источник истины** о структуре. Работает на ПРОИЗВОЛЬНОЙ КР, без
эталонного JSON, поэтому ловит структурные баги (потерю/перекос разделов, утечку
тела в заголовок) автоматически на новых файлах.

```
python validate.py путь/к/КРXXX.pdf            # прогнать парсер на PDF и сверить
python validate.py путь/к/КРXXX.pdf --json out.json   # сверить готовый JSON
python validate.py                             # все *.pdf в tests/pdfs (без хардкода имён)
```

Алгоритм: извлечь блок «Оглавление» (учёт точек-лидеров, переноса заголовка и
оторванного номера), разобрать в ожидаемые разделы (номер+заголовок), собрать
фактическое дерево и классифицировать расхождения:

| класс              | значение                                                        | вердикт |
|--------------------|-----------------------------------------------------------------|---------|
| `MISSING`          | номер+заголовок есть в оглавлении и в теле, но раздел потерян    | FAIL    |
| `HIERARCHY_BROKEN` | у узла N.N.N родитель в дереве ≠ N.N                             | FAIL    |
| `TITLE_BLEED`      | в title маркер списка / «Рекомендуется…» / код медуслуги         | FAIL    |
| `PHANTOM_SECTION`  | раздел не из оглавления, дублирующий номер подтверждённого       | FAIL    |
| `DUPLICATE`        | один номер повторён с тем же (пустым) заголовком                 | FAIL    |
| `SOURCE_DEFECT`    | дубль/пропуск/перенумерация в самом оглавлении или теле          | WARN    |
| `EXTRA` / `TITLE_MISMATCH` | раздел не из оглавления / расхождение заголовка по номеру | WARN    |

Плюс структурные инварианты для любого файла (даже без читаемого оглавления):
покрытие, чистота заголовков, отсутствие настоящих дублей. Новый PDF в `tests/pdfs`
подхватывается автоматически — имена файлов не захардкожены.

Парсинг оглавления вынесен в общий модуль `crparser/engine/toc.py`: им пользуется
и валидатор, и САМ парсер — оглавление служит арбитром при приёме заголовка, чтобы
нумерованные пункты списков из прозы («1.1 КТ признаки…») не становились фантомными
разделами рядом с настоящими (для подуровней, не подтверждённых оглавлением и
стоящих вне своего верхнего раздела). Легитимные коллизии источника (один номер с
двумя разными заголовками в оглавлении) при этом сохраняются с `warning`.

`validate_headings.py` — точечные критерии многострочных заголовков (КР79_2 +
регрессионный набор): PASS/FAIL по каждому пункту.

## Границы

- Реализован один профиль — КР. Профиль монографии не пишется, но место под него
  в архитектуре оставлено (папка `profiles/`, базовый класс).
- Таблицы — best-effort: сохраняются сырыми (`raw_text`), без разбора на ячейки.
- Стек: PyMuPDF (текст/шрифты/bbox), pdfplumber (таблицы), openpyxl (реестр).
