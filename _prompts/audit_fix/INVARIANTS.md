# Инварианты проекта: накопленные находки

**Как пользоваться.** Этот файл читается **перед каждым промптом** и дополняется **после
каждого**. Промпты — это гипотезы о коде, написанные до его исполнения. Всё, что выясняется
во время работы, обязано попасть сюда, иначе следующий промпт наступит на те же грабли.

**Правило исполнителя:** перед началом любого промпта — прочитать `PLAN.md` и этот файл.
После завершения — дописать сюда всё, что оказалось не так, как ожидалось. Новая находка,
не записанная сюда, считается потерянной.

## I1. Контрольная группа: файлы, которые НИ ОДИН гейт не имеет права утопить

Любой новый гейт, порог или детектор обязан оставить эти файлы в PASS. Если после правки
хоть один ушёл — **чинить правку, а не двигать порог**.

| Файл | Чем ценен |
|---|---|
| `КР802_1`, `КР845_1`, `КР901_1`, `КР1000_1` | здоровые born-digital; у КР1000_1 66+ **легитимных** латинских токенов и 0 §-токенов — ловит детекторы порчи, срабатывающие на нормальной латинице |
| `КР66_4`, `КР876_1` | **римская нумерация глав**, приведённая парсером к арабской. 8 разделов верхнего уровня, 38 и 22 узла в дереве — структура полная. Ловят гейты, сверяющие каноничность только по арабскому номеру |

Проверять **после каждого** промпта, меняющего валидатор или сегментер.

## I2. Нумерация глав бывает римской. Везде

Не только в оглавлении.
- `validate.py:_NUM_RE` был `^\d+(\.\d+)*$` — римские записи оглавления отбрасывались
  целиком. Отсюда ложный PASS `КР848_1` (29 римских записей → ноль MISSING).
- Парсер приводит римские главы к арабским номерам в `sections`. Значит **сверка «номер из
  TOC ↔ номер в sections» обязана понимать оба алфавита**, иначе даёт ложный MISSING.
- Кириллические гомографы римских цифр (`Х`, `У`, `С`, `І`, `Ѵ`) — типовая порча источника.
  Нормализовать к латинским перед сравнением.
- **Следствие для гейтов:** `CANONICAL_RECALL`, `COLLAPSE`, любая сверка с TOC — все
  обязаны работать с римской нумерацией. Список канонических глав брать из профиля
  (`ClinicalRecommendationProfile.canonical_chapters`), не хардкодить.

## I3. `ocr_pins.json` — формат v2, замены лежат в `map`

Промпт 02 перевёл базу в `{"version": 2, "reviewed_at": ..., "map": {"кривое": "чистое"}}`.
Загрузчик понимает и v1 (плоский dict), и v2.
**Любой код, читающий базу напрямую, обязан брать `map`.** Наивная итерация верхнего уровня
даст ключи `version`/`reviewed_at` и **ноль попаданий** — гейт тихо не сработает.
Проверка: `КР1_4` обязан давать `RESIDUAL_PIN` (`Вагсе1опа`, `ВСЬС`, `СНшс`).

## I4. `parse_toc` тянет за собой гибрид-OCR

`validate.py:parse_toc` → `PdfReader.read()` → **гибрид-OCR** (`pdf_reader.py:180`).
Последствия:
- разбор оглавления **зависит от OCR-стека**. Доказано: у `КР1_4` хеш записей TOC при
  OCR-off — `d9db4b7bf82e`, при OCR-on — `a193891de9ee`. Разные оглавления;
- любой кэш, хранящий результат `parse_toc`, **обязан включать в ключ отпечаток OCR-стека**
  (`ocr._stack_signature()`), иначе молча отдаёт не то оглавление → не тот MISSING →
  не тот статус. TOC-кэш (промпт 00) это учитывает: ключ
  `<pdf_sha12>_<toc_code_sha8>_<ocr_stack_sha8>`;
- PDF читается **дважды** за прогон (парсером и валидатором) — §1.5 аудита. Радикально
  чинит промпт 16 (единый `DocumentView`).

## I5. Доступность Tesseract — молчаливое средозависимое условие

- `ocr.py:_resolve_tesseract()` при отсутствии `TESSERACT_CMD`/`TESSERACT_PATH` **откатывается
  на захардкоженный путь** `~/Tesseract-OCR/tesseract.exe`. Тест «OCR выключен», выставляющий
  только переменную окружения, **лжёт**: OCR остаётся включённым.
- `parser.py:_full_ocr` при недоступном OCR: `if not recoverer.available(): return []` —
  «тихо, поведение как без OCR».
- **Следствие: на машине без Tesseract батч производит ДРУГОЙ корпус и завершается exit 0.**
  Это дыра fail-open на уровне окружения. Закрывается в промпте 05 (правка 3-bis):
  `--require-ocr` по умолчанию, недоступный OCR → `run_integrity_ok = False`, exit 2.
- Тестировать OCR-off только **подменой резолвера** (monkeypatch → None) или отдельным
  процессом с гарантированно недоступным бинарём. Не переменной окружения.

## I6. Парсер и валидатор могут смотреть на РАЗНЫЕ документы

24 файла-скана восстанавливаются **полным OCR** в парсере (`total_chars` 39–513 тыс.,
13–56 секций), но `parse_toc` перечитывает исходный PDF **без полного OCR**, видит пустой
текстовый слой и не может извлечь оглавление → `TOC_NONE`.
**Их структура не проверена против источника ни разу.** Категория карантина
`UNVERIFIABLE_OCR` (промпт 06): в обучающий корпус не попадают **ни при каком статусе**,
пока промпт 16 не устранит двойное чтение PDF.

## I12. Провенанс (промпт 08): что оказалось не так, как ждал промпт

**Именование — `span_uids`, не `line_ids`.** Редакция 2 переименовала `line_ids`→`span_uids`
и `claimed_line_ids`→`claimed_span_uids` (геометрический якорь вместо индекса строки). Схема
из 03 (`cr_schema.json`) и тест D15 из 07a были написаны под СТАРОЕ имя — оба обновлены.
Будущий код (09/10/16) обязан читать `span_uids`.

**Кросс-канальность ВРОЖДЁННАЯ, а не по IoU.** `hybrid_recover` правит `Line.text` ПО МЕСТУ:
native и OCR одной строки — ОДИН объект `Line` → ОДИН `span_uid` → два кандидата
(`text_raw`=битый native, `text`=восстановление). Отдельный IoU-проход (`SPAN_MATCH_IOU` из
текста промпта) для ТЕКУЩЕГО кода НЕ нужен и НЕ реализован. Он понадобится, только если канал
начнёт давать ОТДЕЛЬНЫЙ набор строк (реальный роутер 16) — тогда строки одной области сшивать
по IoU. Подтверждение: КР1_4, один `Line` даёт `{native:"Вагсе1опа", ocr:"Barcelona"}`.

**PageIR строится по ФИНАЛЬНЫМ страницам, в parser, НЕ в read().** `_full_ocr` заменяет
`pages` целиком в `parser.parse()` ПОСЛЕ возврата из `reader.read()`. Поэтому `build_page_ir`
(живёт в pdf_reader) ВЫЗЫВАЕТСЯ из parser на итоговом наборе. Построишь в read() — у 24 сканов
IR будет по пустому нативному слою, а не по OCR.

**Warnings инварианта владения НЕ должны содержать подстроку `ocr`.** Гейт валидатора
OCR_REQUIRED: `any("ocr" in w.lower() for w in doc["warnings"])`. Наши provenance-warnings
имеют префикс `provenance:` и формулировку БЕЗ «ocr» — иначе КАЖДЫЙ документ (у всех есть
сироты) получил бы ложный REVIEW.

**Заявка таблиц — по ПЕРЕСЕЧЕНИЮ bbox, не по «центр внутри».** Сегментер вычитает строки по
`_covered_by_table` (центр в bbox). Возьми тот же предикат для `claimed_span_uids` — дубли
секция↔таблица ИСЧЕЗНУТ (вычтенное только у таблицы, оставленное только у секции). Аудит §4.2
(КР628_2: «Критерии качества» и в `sections[6].text`, и в `tables[1]/[2]`) виден ТОЛЬКО при
ПЕРЕСЕЧЕНИИ: строки, чей центр лёг ВНЕ узкого bbox таблицы (потому и не вычтены), но которые
заходят в её область, честно заявлены дважды. Инвариант ДЕЛАЕТ двойной учёт видимым.

**ExcludedItem — датакласс, но dict-совместим** (`.get`/`[]`/`in`/`__setitem__`): `stats.py`
(`item.get("title")`) и сегментер (`item["text"] += ...`) работают БЕЗ правок. JSON-форма та
же: `{title, text, span_uids}` (span_uids В КОНЦЕ). `--no-provenance` даёт прежнюю форму
байт-в-байт (включая фильтрацию provenance-warnings).

**reconcile_score меряет СОХРАННОСТЬ, а не корректность.** A (сетка pdfplumber) и B (IR-спаны)
читают ОДИН нативный слой → глиф-битая таблица даёт score≈1.0 (обе стороны видят одинаковый
мусор ШСС/Т1а/МО) — это НОРМА, корректность глифов = зона 13. **Прежний пин «медиана score ≠ 1.0»
ОТМЕНЁН**: два независимых экстрактора на чистой рамочной таблице ОБЯЗАНЫ сойтись на ~1.0, медиана
≈1.0 — норма. Правильная проверка — ЛЕВЫЙ ХВОСТ (score НИЗКИЙ там, где A не захватила текст B):
- **ГЛАВНЫЙ пин: КР628_2 Table 1 (стр.24-30)** — сейчас 194 симв, одна шапка от 7-страничной
  таблицы. score ОБЯЗАН быть низким: в B есть лекарственные строки, которых нет в усечённой A.
  Если ≈1.0 — reconcile сломан (ничего не меряет). Вычитание при низком score БЛОКИРУЕТСЯ →
  строки остаются в теле.
- **КР1_4 Table 2** — до continues_table часть строк отсутствует → score низкий.
- **bbox-overcapture** (bbox захватил соседнюю прозу) — score падает: в B токены прозы, которых
  нет в сетке A → вычитание блокируется, проза остаётся в теле («никогда не потерять»).
Если эти три НЕ дают низкий score — reconcile не меряет ничего, сколько бы ни было зелёных тестов.
Ключ: **B = ВСЕ IR-спаны геометрически внутри bbox** (включая overcapture-прозу и строки, что A
пропустила); A = токены сетки pdfplumber; score = |B∩A|/|B|.

**Проверено (КР628_2 Table 1): B = РЕГИОН ансамбля, а НЕ усечённый bbox find_tables.** Рамочная
детекция дала bbox только ~118pt (одна ШАПКА, 194 симв); лекарственные строки семистраничной
таблицы сейчас лежат в SECTIONS как проза (все 7 препаратов — латанопрост/тимолол/… — в тексте
секций, в tables нет). Если reconcile-ить B=спаны-в-этом-bbox против A=шапка → B≈A → score≈1.0,
reconcile СЛЕП к усечению. Значит регион B для reconcile определяет ПЕР-СТРАНИЧНЫЙ безрамочный
ансамбль (caption «Таблица 1» + колоночная структура, extent через стр.24-30 / continues_table),
а НЕ bbox find_tables. **reconcile и безрамочный ансамбль СЦЕПЛЕНЫ:** ансамбль задаёт extent
региона (B), reconcile проверяет, что сетка A этот регион захватила. Пин КР628_2 Table 1: после
09 либо строки препаратов в raw_text (ансамбль нашёл, score высокий), либо остались в SECTIONS

## I14. Coverage v2 (промпт 10) — span-union: что оказалось не так, как ждал промпт

**coverage_v2 считается в parser-time из page_ir, НЕ пересчитывается валидатором.** JSON-блок
`provenance` несёт только `spans_total` (ЧИСЛО) и по-страничные счётчики — НЕ список span_uid и
НЕ их текст. Значит множество S (все спаны) и веса/тексты сирот из JSON НЕ восстановить.
`stats.py:coverage_v2_from_objects` считает по page_ir (вес спана = длина текста ВЫБРАННОГО
канала) и кладёт в `stats["coverage_v2"]`; `validate.py:_coverage_v2_gate` его ЧИТАЕТ. Любая
правка формулы coverage_v2 требует ПЕРЕПАРСА корпуса (revalidate не поможет — v2 уже в JSON).

**Аддитивность 10 = +1 ключ `stats.coverage_v2`, strip → БАЙТ-В-БАЙТ baseline (722/722).**
Проверка: `_corpus/check_additive_10.py <backup>`. coverage_v2 ничего не читает деструктивно.

**Псевдо-span только когда provenance НЕТ вообще (синтетика).** `_coverage_v2_core`: если у
любого unit есть span_uid ИЛИ page_ir непуст — режим «реальные span'ы», и unit БЕЗ span'ов

## I16. heading_order_valid подключён (промпт 11b) — почему POST-PASS, а не acceptance

**Проверка в LINEAR-порядке коммита ШУМНА (~193 файла, >50 — пин рубит).** Замер:
27% корпуса «нарушают» монотонность, если проверять `heading_order_valid(num, last)` в
момент коммита секции (flush_open). Половина — РАВНЫЕ номера (дубли-коллизии, УЖЕ
покрыты warning'ом «коллизия номера»), половина — «обратные» в порядке ЧТЕНИЯ, где
подразделы разных веток чередуются (артефакт линейного порядка, не реальная аномалия).

**Решение: POST-PASS по ДЕРЕВУ (DFS), только СТРОГО-обратный шаг, равные пропускаем.**
`Segmenter._check_heading_order(tree)` идёт по построенному дереву в документном порядке
(`_walk_tree`), сверяет каждый нумерованный узел с предыдущим, warning ТОЛЬКО когда
`num != last И not heading_order_valid(num,last)` (строго-обратный, не дубль). Замер: **17
файлов** (≤50 ✓), 0 потерь секций, дельта статусов 0, PASS 529→529 (НЕ вырос), все 6 I1
байт-в-байт (их нарушения были РАВНЫЕ номера → отфильтрованы). Примеры: КР1021_1 (потеряны
главы VI–XI, I10), КР109_2/374_3/603_3 — реальная обратная нумерация источника.

**Guard 11b соблюдён: НЕ отбрасываем молча.** Реальный отсев фантомов уже делают order_ok
(level-1 по max_top), toc_reject (подпункты-списки), `_drop_phantom_duplicates` (конкурирующий
кандидат, подтверждённый TOC). Дублировать отбрасывание = прятать проблемы (пин «PASS не
растёт»). 11b лишь ДЕЛАЕТ обратный шаг ВИДИМЫМ через warning. Формулировка без «ocr».
D21 переведён из xfail в passed; регресс 57 passed / 0 xfail.

## I19. ТРИ класса латинской порчи — A1/A2/B (13b). A2 назван поздно, чинится ТОЛЬКО шаблоном

Замер 13/13b обнажил, что «класс A» — это ДВА разных класса с разными чинильщиками:

| Класс | Что в PDF | /ToUnicode | Шрифт (agreement) | Чинит |
|---|---|---|---|---|
| **A1** битый маппинг | глиф латинский, код врёт | ВРЁТ | битый (**0.00–0.01**) | font-repair (контур), eng-OCR |
| **A2** исходный гомограф | глиф кириллический (набран с рус. раскладки) | ЧЕСТЕН | **ЧЕСТЕН (0.97–1.0)** | **ТОЛЬКО шаблон сущности** |
| **B** утрата символов | символ отсутствует | — | — | eng-OCR |

**A2 — открытие: контрольная группа I1 (born-digital, PASS, шрифт ЧЕСТЕН 0.974–1.0) несёт
битые ATC** `C10AС`/`N06AА`/`D08АС02` — кириллические С/А в латинских слотах кода. Ни

не чинят. Автор набрал код с русской раскладки — гомограф лёг в источник.

**A2 чинится ТОЛЬКО шаблоном сущности, и это самый дешёвый/безопасный фикс проекта:**
ATC = `[A-Z]\d\d[A-Z]{2}\d\d`, МКБ = `[A-Z]\d\d(\.\d)?`, TNM = `[TNMG][0-4xX][a-d]?`. Внутри
РАСПОЗНАННОГО шаблона все буквенные слоты ОБЯЗАНЫ быть латинскими → кир-гомограф в слоте =
однозначно латинская буква (тот же глиф). Замена только ВНУТРИ шаблона → за его пределами
портить нечего → **false_substitution = 0 ПО ПОСТРОЕНИЮ** (как и agreement-гейт font-repair).
Судя по I1, A2 — основная масса тех 72% критических из I18. **A2-нормализация идёт ПЕРВОЙ в
13b, до eng-OCR по кропу.**

**Гомограф ЦИФРЫ в ЦИФРОВОМ слоте шаблона (`coerce_entity`, latinnorm.py).** Грамматика
TNM после M допускает лишь 0/1/x → `MO` невалиден, `M0` валиден → `О` ОБЯЗАНА быть нулём
(следствие шаблона, НЕ догадка → fsr=0). Карта O/o→0, l/I/L→1, З→3, б/Ь→6. Применять ТОЛЬКО
в цифровом слоте распознанного шаблона И только если итог валиден. Чинит `МО`→`M0` (КР1_4,
13× — метастазы M0!), `ТО`→`T0`, и `SOLEC`→`S01EC` (eng-OCR O→0,L→1). **Буквенный слот с
цифрой НЕ трогаем** (`0`→`D` или `O`? неоднозначно → eng-OCR): `037.6`/`501ЕС` native →

## I20. Latin recovery РЕЗОЛВЕР (13b интеграция) — что оказалось не так, как ждал промпт

слово/аббревиатура → НЕ латинизировать** (ГЦР/РФ/СНВС повторяются; хап/ЫазаШ/8рае1И — hapax

**TNM без цифры (МО/ТО/СО) — код ТОЛЬКО в staging-регионе** (is_tnm_region: кортеж `Т.. N. М.`
ИЛИ >=2 определения категории `Мх -`). Иначе МО=«мед.организация», ТО=«то». Цифро-гомограф
МО→M0 идёт в `self._tnm` (контекстную карту), применяется ЛИШЬ где tnm_ok. Т1а (с цифрой) —
однозначно TNM, глобально.

**Ведущий цифро-глиф в БУКВЕННОМ слоте (037.6/501ЕС/801ЕС): цифра отрендерена буквой** (D/S→0/5/8).
Шаблон бессилен (буква-слот), нужен eng-OCR. Узкие правила `_RX_LEAD_ICD=^0\d\d`, `_RX_LEAD_ATC=
^[58]\d\d[букв]{2}` (чтобы не ловить числа 324/100). `_code_from_eng` сверяет eng-кандидат с
цифро-СИГНАТУРОЙ core (digit-glyph-буквы б→6 тоже цифры), допуская расхождение ведущего символа.
ICD/ATC ТРЕБУЮТ реальную цифру (иначе «ООО»(рус.) = «O00»(icd) FP). `_strip_edges` снимает ВСЮ
краевую пунктуацию по `\W` (внутренние `./[` целы): `(Н40.0б)[` → ядро `Н40.0б`.

**Римские стадии Н-Ш→II-III, П-1У→II-IV — ЛОССИ (1 глиф → 2-3 римских символа)**, шаблон/контур
бессильны. Детектим ЦЕЛЫЙ токен ДО дефис-сегментации (`_is_roman_stage`: обе стороны из римско-
гомографного набора `IVXLCM+НШПУХСМІ1lОо0` + кириллица), чиним eng-OCR по кропу, принимаем ТОЛЬКО
валидную римскую форму `[IVX]+-[IVX]+` (иначе не трогаем). needs_review. Пред-проход `_apply` до
сегментации. Дефис/тире в выводе — как дал OCR (тест сверяет по нормализованному тире).

**ГЕНЫ (СТЪА4→CTLA4, РИ1→PD1) — ТОЛЬКО через E3** (чистое вхождение целевой формы в документе):
gene-форма (`_looks_critical_term`+кириллица) применяется, лишь если eng-выровненное слово ∈
doc-vocab. Иначе рус.«ВГВ2000»/«ГЦР7» латинизировался бы по OCR-мусору. Ген БЕЗ E3 → в очередь,
НЕ карантин. Ген-форма с хвостовой цифрой у freq≥3-аббревиатуры (ГЦР7=ГЦР+сноска) — снимаем.

**Release-block (unresolved_critical) ТОЛЬКО при СИЛЬНОЙ улике: `code_alphabet_violation`** (кир.
гомограф в ВАЛИДНОМ шаблоне ICD/ATC/TNM) + не разрешён. Слабые улики (ген-форма, ведущий глиф —
001/Уо1.22) неоднозначны: в очередь, НЕ карантин. Иначе цитаты «Vol.22»/числа топили бы док.

**Р2 РЕШЕНО: eng-OCR по кропу снял >80% остатка → LLM НЕ нужна.** Итог механизма (КР1_4/КР628_2):
25/27 и 19/19 Group A. Единственный НЕ взятый безопасно+обобщённо — **UICC←ШСС** (all-caps лосси-
акроним, freq-защищён, неотличим от рус. аббревиатуры: любой all-caps→eng-OCR-пасс латинизировал бы
СОД→COD, ВГД→BID и т.п. — Group B-регресс). Оставлен в очередь на человека/gold (14). Это ВАЛИДНЫЙ
исход (NO-GO на 1 токене), не провал: механизм генерик и безопасен, а не хардкод имён (I11).

**Верификация РЕЗОЛВЕРА — по РЕАЛЬНОМУ пайплайну, не по JSON-харнессу.** JSON-реконструкция сцен
из outout/ расходится с fresh-parse (full-OCR ре-сегментация). Group A мерить в ОБУЧАЕМОЙ ЗОНЕ
(sections/tables/metadata/appendices), НЕ по всему JSON: `037.6`/`МО` в references остаются (их не
трогаем — решение команды) и ложно «проваливают» absent-проверку по всему документу.

**ТОКЕН-СКЛЕЙКИ — второй большой источник Group B FP (нашлось на I1 КР66_4).** OCR склеивает
слово+цитату/комбинацию: `Пиперациллин+[Тазобактам`, `стерильность)[80`, `цефтазидим+[авибактам`,
`19лет`. Скобочное/цифро-правило `_cyr_orphan` их ловило → eng-OCR латинизировал рус. препараты в
МУСОР (I1 корёжился!). Фикс: (1) сегментация режет `+` и `()` (границы склеек) — но НЕ `[`
(нужен для `1п[епог`); (2) скобочное правило требует ЦИФРУ в слове; (3) цифро-правило исключает
`\d+[а-яё]+` (число+рус.слово `19лет`/`80мл`). После: КР66_4 10 FP→1 легит-код (`р63`→`P63`),
КР1000_1 0. **Урок: healthy I1 обязан давать ~0 правок; любая правка на I1 — сначала подозрение
на FP, глазами.**

**СКЛЕЙКИ — цельный класс FP, вычищался итеративно по корпусу (2422→~0 真-рус.).** Все сигналы
cyr_orphan обязаны отличать ГЛИФ-ошибку от границы-склейки:
- скобка/слэш `[/`: за ней БУКВА (`1п[епог`,`8Иа//ег`=`/е`) = глиф; за ней ЦИФРА (`стационар[1,2`,
  `лечение[4`) = ЦИТАТА рус.слова → НЕ трогаем;
- camelCase: строчная→ЗАГЛАВНАЯ-КИРИЛЛИЦА (`ТетрогаШ`), но НЕ латиница (`неуточненнаяD56`=код) и
  НЕ перед длинным (>=4) строчным (`эндокардитаРекомендуется`=два рус.слова);
- цифра ВНУТРИ: БУКВА-ЦИФРА-БУКВА (`е1И`), НЕ хвост (`исследования12`) и НЕ ведущий номер
  (`3Эозинофильные`, КР1000_1!). Сегментация режет `+ ( ) *` (`тимолол**0,25`,`препарат+[комб`).
**Р2 ключевой урок: остаток «85% кириллицы, задетектировано» на 90% — ЛЕГИТ порча латиницы**
(`Ыотесйса1`=Biomedical, URL'ы) в reference-heavy доках; 真-рус. FP (`синдромеВ`,`МанзюкЛ`) —
меньшинство, все needs_review+очередь (не auto) → Group B (auto=fsr0) держится, человек досмотрит.

**КРИТИЧЕСКОЕ: latin recovery ДОЛЖЕН идти ДО stats.compute** (parser шаг 4c). Мутация текста
после подсчёта included_chars/table_chars → STATS_MISMATCH FAIL у 431 док в первом полном прогоне.
После переноса: дельта статусов ~0 (только 1 REVIEW→FAIL: КР119_3 — правка в ЗАГОЛОВКЕ ломала
TOC-title-match MISSING; починено вычисткой FP). PASS 529 стабилен, I1 все PASS.


## I21. Класс C5 и почему ВИЗУАЛЬНЫЕ методы его НЕ берут (NO-GO, замер recall)

**Замер recall детектора** (`_corpus/detector_recall.md`, слепой eng-OCR по 32 120 строкам зоны,
10 док): **recall 60.2%**. 88% пропусков — класс **C5: латинское слово ЦЕЛИКОМ кириллицей**
(`рока`->portal, `йуег`->liver, `уапсез`->varices, `ШСС`->UICC) БЕЗ структурной аномалии.
Anomaly-детекторы (Ы-старт/camelCase/цифра-внутри) их не видят ПО ПОСТРОЕНИЮ — это цена
безопасности Group B, а не баг.

**ГЕЙТ 1 (генератор) — БИТЫЙ ШРИФТ — РАБОТАЕТ и переиспользуем.** Замер: все C5-пропуски лежат
в шрифтах с agreement=0.000-0.009 (здоровые 0.97-1.0, разрыв огромен, промежутка нет). 32% док.
имеют >=1 битый шрифт, **68% — все шрифты честные -> ноль кандидатов, ноль OCR** (Group B по
построению для 2/3 корпуса). Шрифт как генератор СИЛЬНО лучше словаря: не нужны ни аномалии,
ни морфология.

**НО Group B НЕ МОЖЕТ держаться на гейте 1** (проверено, КР1_4): в битом документе ЧЕСТНОГО
шрифта НЕТ — русский текст (`Клинические`, `печени`, `стеатогепатита`) лежит в ТОМ ЖЕ битом
шрифте, что и порченая латиница. Флагать «всё в битом шрифте» = флагать весь русский.

**ГЕЙТ 2 (precision) ПРОВАЛИЛСЯ ДВАЖДЫ — и причина ФУНДАМЕНТАЛЬНА:**
1. рукодельная карта транслитерации -> **196 рус. словоформ латинизировано** (`пациентов`->
   `nayuenmoe`, `Уровень`->`ypoBeHb`): карта — плохая модель того, что Tesseract делает с глифом;
2. второе мнение движка `-l rus` -> НЕ помогло (**`боль`->`bone`**, `пациентов`->`nayuenmoe`).

**ПОЧЕМУ: порча сидит в /ToUnicode, а ГЛИФЫ РУССКОГО ТЕКСТА РЕНДЕРЯТСЯ ВЕРНО.** На странице
визуально лежит ПРАВИЛЬНЫЙ русский — отличить его от правильной латиницы ВИЗУАЛЬНЫМ методом
НЕЧЕМ (любой OCR читает то же самое). Отличает только ЯЗЫК (словарь/морфология), от которого
отказались ради редких словоформ. **Смена OCR-стека (Docling/Paddle/Surya) не поможет по той же
причине — они прочитают те же пиксели.**

**РЕШЕНИЕ: C5 = NO-GO** (`C5_ENABLED=False`). `боль`->`bone` в медицинском корпусе хуже, чем 40%
непокрытого recall. Включение — только с ЯЗЫКОВЫМ арбитром (морфоанализатор / LLM-ранкер по
кропу: 13b ШАГ 7, промпт 15). Гейт 1 оставлен как фундамент.

**ТЕСТ-СТРАЖ `tests/test_latin_c5_morphology.py`.** Критерий ОБЯЗАН быть НЕЗАВИСИМ от логики
гейта: первая версия теста проверяла гейт ЕГО ЖЕ формулой (translit+словарь) -> была циркулярна
и «проходила» при 196 испорченных словоформах. Рабочий критерий: **токен из 7+ подряд СТРОЧНЫХ
кириллических букв = русское слово, C5 не имеет права его трогать** (порченая латиница почти
всегда несёт заглавную/цифру/чужой глиф; `рока`/`уапсез` короче 7).

**ФИКС B (сделан, `f7a68f8`): в очередь идёт ЛЮБОЙ неразрешённый задетектированный спан**, не
только критический (было: некритический термин, не поддавшийся резолюции, исчезал без следа —
12% пропусков). Очередь != карантин: блокирует релиз по-прежнему только сильная улика.

**Урок замера: слепой OCR по русскому корпусу даёт ~115 000 транслит-артефактов на 32 120 строк.**
Инструмент замера правился 3 раза (25.5% -> 59.6% -> 60.2%); первые две версии врали (транслит-
артефакты, сбой выравнивания на односимвольных токенах). Любой замер «OCR vs текст» без
RU-словаря и санити выравнивания врёт В РАЗЫ.

## I22. C5 ВКЛЮЧЁН языковым арбитром (pymorphy3). Чем он оказался НЕ ТЕМ, что ждали

**Решение I21 «C5 = NO-GO» отменено, но его ДИАГНОЗ был верен** и остаётся в силе: визуальным
методом русский от латиницы в битом документе не отличить (глифы русского рендерятся ВЕРНО,
порча в /ToUnicode). Нужен ЯЗЫКОВОЙ арбитр — им стал `pymorphy3` (`crparser/engine/rumorph.py`,
`pip install pymorphy3 pymorphy3-dicts-ru`: локально, офлайн, детерминированно, бесплатно —
это НЕ E3). Гейт 2 = `word_is_known()`. `боль` — валидная рус. словоформа -> защищена ->
**`боль`->`bone` невозможен**; `пациентов`, `Уровень`, `Клинические`, `печени`, `СОСТАВ`, `РФ`
— тоже (замерено поимённо).

**ГЛАВНОЕ, ЧТО ОКАЗАЛОСЬ НЕ ТАК: «pymorphy знает любую словоформу независимо от частоты» —
ВЕРНО ТОЛЬКО ДЛЯ ЛЕММ ИЗ OpenCorpora, А МЕДИЦИНСКОЙ ЛЕКСИКИ ТАМ НЕТ.** Замер:

| токен | word_is_known |
|---|---|
| боль / пациентов / Уровень / Клинические / печени / СОСТАВ / РФ | **True** (защищены) |
| гепатоцеллюлярном / стеатогепатита / мультикиназными | **False** |
| холангиокарцинома / иммуногистохимического / ГЦР / СНВС | **False** |

`word_is_known()` — это СЛОВАРЬ (5 млн словоформ общего языка), а не генератор морфологии для
незнакомых основ. Ровно тот аргумент, которым словарь отвергали («редкая форма
`гепатоцеллюлярном` в словарь не попадёт»), бьёт и по pymorphy. **Гейт 2 закрывает ОБЩИЙ
русский (и ровно те слова, на которых канал падал), а НЕ медицинский.** Не расширять его
зону ответственности в комментариях и в голове.

**Предсказатель по суффиксам подтверждён негодным — но НЕ «принимает всё подряд», а хуже:
он УВЕРЕН В ПОРЧЕ.** `parse('оезорЬадиз')[0]`: is_known=False, **score=1.000**,
`NOUN,anim,masc,Name` (принял за фамилию) — выше, чем у настоящего `гепатоцеллюлярном`
(0.494). Гейт по `parse()`/score утопил бы русский и пропустил порчу. **Только
`word_is_known()`.**

**МЕДИЦИНСКИЙ РУССКИЙ ДЕРЖИТ ПРАВИЛО ФОРМЫ, А НЕ СЛОВАРЬ: 7+ подряд СТРОЧНЫХ кириллических =
русское слово, C5 не трогает НИКОГДА.** `гепатоцеллюлярном`/`стеатогепатита`/
`холангиокарцинома`/`иммуногистохимического` — все 7+ строчных -> класс неприкосновенен ПО
ПОСТРОЕНИЮ (тот же приём fsr=0, что у A2-шаблона, I19). **Цена правила ИЗМЕРЕНА и принята:**
оно ошибается на порче без заглавной/цифры/чужого глифа — `аззеззшеп`(=assessment). Такой
токен НЕ латинизируется, но и НЕ теряется: уходит в очередь с кропом (`c5_long_lowercase`).

**ALL-CAPS кириллица -> НЕ кандидат ПО ПОСТРОЕНИЮ (рус. аббревиатура).** Для all-caps НЕ
работает ни гейт 2 (`ГЦР`/`СНВС` -> known=False), ни гейт 3: eng-OCR даёт РЕАЛЬНОЕ лат. слово
(`СОД`->COD, `ВГД`->BID), и LAT-словарь его ПРОПУСТИТ. Частота (freq>=3) прикрывает только
повторяющиеся (ГЦР=125, СНВС=16), редкую аббревиатуру — нет. **Ценой правила ОСОЗНАННО уходит
`ШСС`->UICC** (единственный all-caps класса C5, freq=3 — ровно на пороге): лосси (4 глифа -> 3
симв.), контур бессилен, от рус. аббревиатуры неотличим. Двигать порог freq ради этого пина
ЗАПРЕЩЕНО (I11) — I20 уже признал этот исход валидным: место ШСС в очереди на человека.

**`-l rus` (второе мнение движка) УБРАН — он не только не защищал, но и ВРЕДИЛ recall:** читая
реально-латинские глифы `UICC` кириллицей, он «подтверждал» родной `ШСС` и блокировал
ПРАВИЛЬНУЮ починку. Минус один OCR-вызов на строку.

**FAIL-CLOSED (I5): нет pymorphy -> канал C5 выключен ЦЕЛИКОМ** (`c5_active()`), а
`word_is_known` при недоступном арбитре отвечает **True** (=«русский, не трогать»). Трактовать
«пакета нет» как «слово неизвестно» = латинизировать русский на машине без зависимости и молча
произвести ДРУГОЙ корпус — ровно дыра I5.

**LAT-СЛОВАРЬ КОРПУСА ЗАГРЯЗНЁН ТРАНСЛИТ-МУСОРОМ -> ГЕЙТ 3 НЕ ЯВЛЯЕТСЯ ЗАЩИТОЙ GROUP B.**
Проверено поимённо в `crparser/data/latin_vocab.json` (5005 слов): `nayuenmoe` (**=пациентов**,
тот самый пин катастрофы!), `ypobehb` (**=Уровень**), `ajit`(АЛТ), `cba3h`(связи), `mozo`(того),
`heit`(ней) — **ВСЕ ЕСТЬ В СЛОВАРЕ**. Утверждение из `detector_recall.md` («транслит-мусор в
извлечённом тексте не встречается никогда -> в словарь не попадает») **ЛОЖНО**: в baseline есть
ОБРАТНАЯ глиф-порча (кириллица->ASCII, `pseudo_ascii_tokens`), из-за неё мусор буквально лежит в
тексте и проходит фильтр «>=3 док.».
- **Следствие 1: это МЕХАНИЧЕСКОЕ объяснение катастрофы 196 словоформ.** Гейт LAT-словаря был на
  месте и `пациентов`->`nayuenmoe` ПРОПУСТИЛ — потому что `nayuenmoe` в словаре ЕСТЬ. Дело не в
  отсутствии гейта, а в том, что словарь построен по ПОРЧЕНОМУ корпусу.
- **Следствие 2: Group B держит ТОЛЬКО гейт 2.** Замерено: `боль`->`bone` — транслит-гейт НЕ
  блокирует (sim 0.50 < 0.62), LAT-словарь ПРОПУСКАЕТ (`bone` — настоящее слово). Единственный,
  кто говорит «нет», — pymorphy. То же у `рока`->`portal` (sim 0.50, `portal` в словаре).
- **Следствие 3: корпусный RU-словарь (>=3 док.) НЕЛЬЗЯ вносить в гейт** — на нём стоит
  НЕЗАВИСИМЫЙ тест (и он же — дискриминатор замера recall, шаг (2) в `work()`). Внесёшь в гейт —
  единственный эмпирический страж станет циркулярным. Это АРХИТЕКТУРНАЯ ГРАНИЦА, не случайность.
- Замер recall от загрязнения НЕ страдает: там RU-словарь проверяется РАНЬШЕ LAT-словаря.

**ТЕСТЫ: две прежние редакции `test_latin_c5_morphology.py` СРАВНИВАЛИ `_translit(w)` САМ С
СОБОЙ** (`_similar(_translit(w), _translit(w))` == 1.0 ВСЕГДА) -> проходили при ЛЮБОМ состоянии
кода и зеленели, когда канал латинизировал 196 словоформ. Удалены. **Тест-страж «7+ строчных»
СОВПАДАЕТ с правилом 4 гейта -> проходит ПО ПОСТРОЕНИЮ и эмпирикой НЕ является** (его роль —
не дать снять правило молча). Эмпирическую нагрузку несёт **корпусный словарь русского**
(слово, чисто встречающееся в >=3 док. baseline): он не совпадает ни с одним гейтом (гейты
смотрят частоту ВНУТРИ документа, OpenCorpora и форму токена) -> МОЖЕТ упасть. Не удалять.

**Критерий «7+ строчных» НЕЛЬЗЯ применять к `.lower()`-копии токена.** Прежний тест делал
`src.lower()` и ТОЛЬКО ПОТОМ проверял «строчные кириллические» — это уничтожает ровно тот
признак, по которому порча отличается от русского (заглавная ВНУТРИ токена): `оезорЬадиз`,
`КеПгогк`, `Бхзеазе` давали ложный «русский» и завалили бы КОРРЕКТНЫЕ починки.

## I23. Гейт 3 был дырявым ДВАЖДЫ: грязный словарь + E3-право на молчаливую замену

Два НЕЗАВИСИМЫХ дефекта precision-гейта термин-канала. Первый чинится словарём, второй —
НЕТ (и это главное: чистый словарь его НЕ ловит).

### (1) LAT-словарь собирался по ПОРЧЕНОМУ источнику

`crparser/data/latin_vocab.json` строился по ВСЕМУ baseline -> содержал `nayuenmoe`
(=пациентов), `ypobehb`(=Уровень), `ajit`(=АЛТ), `mozo`(=того), `heit`, `cba3h`. Гейт

что `nayuenmoe` в словаре БЫЛ. **Гейт, построенный по порченому корпусу, легализует порчу.**

pseudo-ascii только при ТОТАЛЬНОЙ порче (плотностной порог), а тут порча ЛОКАЛЬНАЯ. Фильтр
по этому флагу — **no-op** (словарь вышел бы байт-в-байт прежним). `glyph_tokens` — тоже 0.

### (2) E3 давал право на МОЛЧАЛИВУЮ замену при ЛЮБОЙ похожести — хуже словаря

Было: `uncertain = not (sim >= 0.8 or e3)`. **E3 = «слово встречается где-то В ЭТОМ ЖЕ
документе»**, а `the`/`and`/`for`/`Vol` есть в любом док. с англ. ссылками -> **ЛЮБОЙ сбой
выравнивания давал auto-замену термина соседним словом строки.** Замер (4801 term-замена):
auto=467, из них **383 разрешены ИМЕННО E3**, и **307 из них при sim<0.5**. Глазами:
`Ыуег`->`the`, `НаетоггЬаде`->`Guideline`, `аи1о1ттипе`->`overlap`, `аз50с1а1ес1`->`from`,
`с!еуе1ортеп1`->`Organization`, `зуз1еш`->`long-term`.
**ЧИСТЫЙ СЛОВАРЬ ЭТОГО НЕ ЛОВИТ И НЕ МОЖЕТ: `the` — настоящее лат. слово.** Лечится только
уликой НА САМОМ ТОКЕНЕ: `uncertain = sim < C5_AUTO_SIM(0.8)`. Цена — верные низко-sim
починки (`Ьийтгщ`->Ludwig sim=0.00) уходят в очередь; размен правильный (человек
подтвердит по кропу, молча испорченный термин — навсегда).

`Tolosa`/`Clancy`/`Rutgeerts`), которых в словаре «>=3 док.» нет и быть не может. Мерить
ущерб этим числом — значит объявить порчей корректные починки. Настоящий ущерб — это (2).

## I25. Почему корпусный RU-словарь НЕ ГОДИТСЯ в гейт (запрет ОБОСНОВАН, но НЕ циркулярностью)

Вопрос был поставлен прямо: «циркулярность сломана фильтром доверенных источников; словарь
покрывает `гепатоцеллюлярный`, чего нет у pymorphy; он может заменить костыль 7+ строчных и
разрулить ШСС без движения порога. Назови причину запрета явно; если это перестраховка —
сними». Проверено замером. **Запрет остаётся, но прежняя формулировка причины БЫЛА НЕВЕРНА.**

**«Циркулярность» — НЕ причина, и её надо перестать так называть.** Фильтр доверенных
чинит ЗАГРЯЗНЕНИЕ, а не циркулярность: если гейт защищает всё, что в словаре, то ни одна
C5-правка НЕ МОЖЕТ иметь источник в словаре -> тест проходит ПО ПОСТРОЕНИЮ при любой чистоте
источника. Циркулярность — свойство «гейт и тест делят критерий», и она РЕШАЕМА (held-out:
словарь гейта по одной половине доверенных, словарь теста — по другой). Т.е. это довод
дизайна тестов, а не довод безопасности, и сам по себе запрет не обосновывает.

**НАСТОЯЩАЯ ПРИЧИНА 1 — ПОКРЫТИЕ. Словарь СЛАБЕЕ правил, которые он бы заменил** (замер):
- **редкие мед. словоформы: 9 из 16 НЕ покрыты** ни словарём, ни pymorphy —
  `гепатоцеллюлярную`, `гепатоцеллюлярными`, `стеатогепатитом`, `холангиокарциномы`,
  `холангиокарциномой`, `мультикиназными`, `трансартериальной`, `химиоэмболизации`. Словарь
  знает ИМЕНИТЕЛЬНЫЙ (`холангиокарцинома` есть), а косвенные падежи — нет. **Исходный
  аргумент против словарей (редкая форма не попадёт) ПОДТВЕРДИЛСЯ на чистом словаре тоже.**
- **цена снятия правила «7+ строчных»: 16 464 УНИКАЛЬНЫХ токена (30 193 вхождения)** в
  битых документах — 7+ строчных, НЕТ в RU-словаре И НЕ знает pymorphy. Глазами это
  РЕАЛЬНЫЙ русский, в основном лекарства и термины: `устекинумаб`, `месалазин`, `озанимод`,
  `кальцитриол`, `формотерол`, `холедохолитиаза`, `псориатического`, `увеитами`,
  `интраокулярная`, `открытоугольной`, `немеланомных`. Снять правило = выставить их под
  латинизацию. Ради ОДНОГО `аззеззшеп`->assessment. Размен абсурден.

**НАСТОЯЩАЯ ПРИЧИНА 2 — БИТЫЕ ДОКУМЕНТЫ ЭТО СМЕЩЁННАЯ, ТЕМАТИЧЕСКИ СВЯЗАННАЯ ВЫБОРКА.**
Догадка «`ШСС` живёт только в порченых -> не в словаре -> не защищён; `ГЦР` живёт и в
доверенных -> защищён» ВЕРНА в первой половине и ЛОЖНА во второй. Замер (док., где токен
встречается):
| токен | доверенных | битых | вердикт словаря |
|---|---|---|---|
| `ШСС`(=UICC) | **0** | 2 | не защищён (пин прошёл бы) |
| **`ГЦР`** | **0** | 4 | **НЕ ЗАЩИЩЁН -> ЛАТИНИЗИРОВАН** (125 вхождений в КР1_4!) |
| `СНВС` | **0** | 6 | **НЕ ЗАЩИЩЁН -> ЛАТИНИЗИРОВАН** (16 в КР628_2) |
| `УЗИ`/`КТ`/`СОД` | 278/250/32 | — | защищены |
**У `ШСС` и `ГЦР` ОДНА И ТА ЖЕ сигнатура — ноль доверенных документов.** Словарь их
РАЗЛИЧИТЬ НЕ МОЖЕТ В ПРИНЦИПЕ. Причина структурная: термин, сконцентрированный в битых
документах, отсутствует в словаре доверенных — а это ровно САМЫЕ ВАЖНЫЕ термины этих
документов (главный термин КР по ГЦР — «ГЦР»). Правило all-caps держит их ПО ПОСТРОЕНИЮ,
словарь — по случайности выборки.

**НАСТОЯЩАЯ ПРИЧИНА 3 — НАБЛЮДАЕМОСТЬ.** Как ГЕЙТ словарь МОЛЧА проглатывает попытку
латинизировать русское слово. Как ТЕСТ — КРИЧИТ. Для свойства, которое обязано быть НУЛЁМ,
«сообщить» строго лучше «тихо предотвратить»: молчаливая защита прячет тот факт, что канал
ПЫТАЕТСЯ трогать русский. Замер: C5-правок с источником в RU-словаре — **0**, т.е. в гейте
он сегодня не заблокировал бы НИ ОДНОЙ правки (нулевая польза), но лишил бы нас единственного
падающего стража (реальный вред).

**ИТОГ: запрет ОСТАВЛЕН, причина ПЕРЕПИСАНА** (покрытие + смещённая выборка + наблюдаемость,
НЕ циркулярность). `ШСС` остаётся в очереди, `аззеззшеп` остаётся в очереди — оба видимы
человеку с кропом.

## I26. Выравнивание было КОРНЕМ обоих дефектов. Локальный порог похожести тут ВРАЖДЕБЕН

`_align_line` переписан с жадного окна на **глобальное выравнивание (Needleman-Wunsch)**.
Это не «+N% recall», а устранение ИСТОЧНИКА: один и тот же сбой давал И пропуск
`йуег`->liver, И ложную пару `Ыуег`->`the`, которую E3 разрешал применить МОЛЧА (I23).
Старая версия была плоха дважды: при `n == m` равняла ПОЗИЦИОННО, вообще не глядя на
похожесть (одна склейка OCR сдвигала всю строку), иначе шла жадно окном 3 без возврата и
ставила пару даже при sim=0.0.

**ГЛАВНОЕ (контринтуитивно, замерено): локальная похожесть у класса A1 ВРАЖДЕБНА истине.**
Маппинг битого /ToUnicode ПРОИЗВОЛЕН (`й`->l, `у`->i, `е`->v, `г`->e), а `_lat_skeleton`
роняет не-гомографы — `_lat_skeleton('йуег') == _lat_skeleton('Ыуег') == 'ye'`. Отсюда:
| пара | sim | что это |
|---|---|---|
| `йуег` ~ `liver` | **0.20** | ВЕРНАЯ |
| `Ыуег` ~ `the` | **0.33** | ЛОЖНАЯ (та самая E3-катастрофа) |
**Ложная пара ПОХОЖЕЕ верной.** Любой порог, рубящий ложную, рубит и верную. Поэтому в
`_align_line` НЕТ порога похожести — и добавлять его НЕЛЬЗЯ (я добавил `_ALIGN_MIN_PAIR=0.25`
и он СРАЗУ съел верное `йуег`->liver, не тронув ложное `Ыуег`->`the`). Различает ТОЛЬКО
глобальная структура: `The` уже занят токеном `ТЪе` -> `Ыуег` физически не может его взять.
Качество пары решают гейты НИЖЕ (транслит, LAT-словарь, pymorphy, sim>=0.8 для auto).
Проверка — `test_alignment_is_global_not_greedy` на РЕАЛЬНОЙ строке КР1_4 стр.69.

**ГЛОБАЛЬНОЕ ВЫРАВНИВАНИЕ ЖИВЁТ НА ЯКОРЯХ, А СКЕЛЕТ РУССКИЕ ЯКОРЯ УБИВАЕТ.** Первая
редакция NW (похожесть только по скелету) СЛОМАЛА `8Иа//ег`->`Shaffer` (КР628_2 стр.17):
дала `uau`. Разбор: строка 10 native <-> 10 eng, соответствие ИДЕАЛЬНОЕ 1:1, но скелет
роняет не-гомографы -> `_lat_skeleton('или') == ''`, `целесообразно` тоже почти пуст.
**Пустой якорь не совпадает НИ С ЧЕМ**, NW предпочитает разрывы, хвост уезжает на 2 токена;
верный путь проиграл на **0.08**. Т.е. русские слова строки, которые ДОЛЖНЫ были держать
раскладку, не держали ничего.
**Фикс — ДВЕ гипотезы в матрице похожести: `max(скелет, транслит)`.** Для выравнивания (в
отличие от РЕШЕНИЯ) не важно, латинский токен или русский; вопрос «могут ли эти двое быть
одним токеном»: если токен реально латинский — его моделирует СКЕЛЕТ; если реально русский
— eng-OCR его ТРАНСЛИТЕРИРУЕТ (`или`->`uau` sim 0.67, `целесообразно`->`yenecooOpa3vo`),
это моделирует ТРАНСЛИТ. Максимум возвращает якоря. После фикса ОБЕ строки верны
одновременно: `8Иа//ег`->Shaffer И `йуег`->liver. Тест `test_alignment_anchors_on_russian_via_translit`.

## I28. Независимость ансамбля проверяется ПРОТИВ РЕЖИМА ОТКАЗА, а не по «инструменты разные»

Правило (обобщение находки I27). Два инструмента, объявленные «независимыми», могут иметь
ОБЩИЙ режим отказа — тогда их согласие НЕ является подтверждением, а ЭХОМ. Проверять
независимость обязательно ПРОТИВ КОНКРЕТНОГО режима отказа, а не выводить из того, что
инструменты разные.

Пример (I27): AND-гейт полагался на «VLM И независимый Tesseract `-l eng`». На ГОМОГЛИФНОЙ
кириллице оба ТРАНСЛИТЕРИРУЮТ одинаково (`связанных`->`CBAZAHHBIX`) — общий режим отказа
«визуальный метод не отличает кириллицу от её латинского двойника» (I21). Tesseract тут —
эхо VLM, а не свидетель. Голоса, которые ДОЛЖНЫ были быть независимыми, скоррелированы
ИМЕННО там, где нужна защита. Разными были ИНСТРУМЕНТЫ, не РЕЖИМ.

Как применять: для каждого ансамбля-гейта назвать режим отказа, который он должен ловить,
и проверить, что голоса расходятся ИМЕННО на нём (а не на лёгких случаях). Если сходятся —
добавить голос ДРУГОЙ природы (для визуального провала — языковой: pymorphy/словарь).

## I29. Гейт арбитра: гомоглифы ВЫВОДИТЬ ИЗ _CYR2LAT; тест по ВСЕМУ токену; стадии — стоп

Адверсарная проверка правки 3b (workflow, 4 независимых атакующих + синтез) нашла 4 вещи —
все в `_source_is_russian` (`_corpus/vlm_pilot.py`); Group B в итоге 0/280, ценность 40.1%.

**(1) Наборы гомоглифов ХАРДКОДИТЬ НЕЛЬЗЯ — выводить из `latinnorm._CYR2LAT`.** Рукодельный
`_HOMO_LOWER='авекмнорстх'` был НЕВЕРЕН: строчные в/к/м/н/т в НИЖНЕМ регистре НЕ двойники
латинских (их VLM читает по различимым пикселям), а у↔y и і↔i — ПРОПУЩЕНЫ (дыра: `оту`/`уро`/
`еуе` обходили гейт). Канон движка: заглавные {Ѕ І Ј А В Е К М Н О Р С Т У Х}, строчные

расходится с движком.

**(2) Пиксель-двусмысленность тестировать по ВСЕМУ токену, не по alpha-буквам.** Тест
`all(c in HOMO for c in letters)` (только буквы) ПЕРЕБЛОКИРОВАЛ 42 задачи битой латиницы с
ЦИФРО-ГЛИФАМИ порчи (`ККА8`=KRAS 8<-S, `8атр1е`=Sample, `ос1е1у`=Society 1<-l): рус.
аббревиатура НЕ содержит 8/1/0 -> цифра ДЕЛАЕТ пиксели однозначными -> заведомо латиница ->
в auto. Тест по всему core (`all(c in HOMO for c in core)`) их освобождает (+7 п.п. ценности,
37->44%), 10 гомоглиф-целей сохраняет.

**(3) НО сперва ОТРЕЗАТЬ приклеенную ЦИТАТУ/ЗНАЧЕНИЕ (склейка токенизатора, I20).** Whole-core
без этого СЛОМАЛ Group B: `МАНК[13`(МАНК+сноска) и `МНО>1,5`(МНО+значение) — рус.
аббревиатуры, но цифра в приклеенной части -> whole-core счёл их латиницей ->
латинизировал (МАНК->MAHK, МНО->MHO — **МНО клинически значимо, свёртываемость**). Фикс:
`re.split(r'[\[\]<>=(){},;]', core)[0]` ДО теста — цифра после скобки/оператора это внешняя
ссылка, а не корруптор буквы. После: МАНК[13/МНО>1,5 блокируются, ККА8/1МРАСТ свободны.

**(4) СТАДИИ (kind=='stage') — КЛИНИЧЕСКИЙ СТОП, в auto НЕ пускать (построчный кроп).** Нога
`_ocr_confirms` НЕ локализована: Tesseract psm=7 по ВСЕЙ строке, `entity_valid('stage')`
принимает ЛЮБОЙ роман -> кандидат-стадия «подтверждается» СОСЕДНЕЙ стадией строки. Замер:
`1-Н`(=I-II, ранняя) -> `III-IV`(поздняя, соседа) — подмена, меняющая курабельность. 7/84
auto пилота — стадии. Пока кроп построчный — стадию в очередь. **ПРОД чинит ПОСЛОВНЫМ кропом**
(OCR читает лишь целевое слово) — тогда снять стоп + сверять роман-структуру источник↔кандидат.
Это ОРТОГОНАЛЬНО правке гомоглифов, но подтверждённая клиническая дыра — БЛОКИРУЕТ прод-GO.

**translit-guard (cand==транслит(source) => не auto) ОТКЛОНЁН:** 75 задач, ~72 — верные
латинизации ИМЁН СОБСТВ. (Abe/Carbone/Society), признак не различает язык. `микроРНК` (рус.,
достижим) держит арбитр по различимой `и` — гейт ему не нужен. all-caps У/З-дыра (ССЗ/ЗНО) —
теоретическая: upstream `_c5_protected` all_caps их в очередь не пускает.

**Урок (усиление I28): «независимый OCR» на построчном кропе — НЕ независим ДВАЖДЫ:** он и
транслитерирует как VLM (гомоглифы), и подтверждает СОСЕДА (не локализован). Пословный кроп

## I37. B3a intra-doc self-repair фраз (промпт 17 ШАГ 1) — детерминизм, без OCR/моделей

Канал `intra_doc_selfrepair` в `latinrecovery.py`: порченую фразу чиним по ЧИСТОМУ образцу
ТОЙ ЖЕ фразы в ЭТОМ документе (E3-свидетель). Индекс `_tmpl_first`: максимальные пробеги
чисто-латинских токенов -> под-фразы 2..6 токенов с сильным якорем (>=4 букв, гласная).
Матчинг `_walk_template`: токен шаблона закрывается (1) чистой латиницей, (2) кир-гомографом
(`С`->C, `В`->B), или (3) РУНОМ осколков (>=2 одиночных кир/цифро-токенов) -> заполняет
МНОГОБУКВЕННОЕ слово шаблона. auto ТОЛЬКО при однозначном совпадении + не критично + (нет
GAP ИЛИ freq>=2); иначе needs_review. Применение — СТРОКОВОЙ заменой окна (меняется число
токенов, посегментный `_apply` так не может). Работает под `--latin-recovery`; baseline не тронут.

**КОРРЕКЦИЯ ПЛАНА (клиническая безопасность, проверено по источнику).** Пин промпта «КР1_4 §2.3:
Hepatitis C virus чист во ВСЕХ 5 вхождениях» ОШИБОЧЕН. Факт §2.3: 5 вхождений делятся по РУССКОЙ
букве генотипа — «вируса гепатита **В** (Hepatitis В virus)» ×2 = Hepatitis **B**, «гепатита **С**
(Hepatitis C virus)» ×3 = Hepatitis **C** (одно из них рассыпано: `Hepatitis С у 1 ш з`).
Заставить все 5 в «Hepatitis C virus» = превратить 2 ЛЕГИТ. гепатита B в C — клиническая порча
(путаница HBV/HCV). Верный исход: осколок `у 1 ш з` убран, occ4 -> Hepatitis C virus (C=3),
Hepatitis B остаётся 2. Различающий гомограф (С->C / В->B) СОВПАДАЕТ с русской буквой генотипа —
это и есть свидетель. Тест `test_b3a_selfrepair.py` пинует ОБА: шаттер убран И гепатит B не
сконвертирован в C.

**ГРАБЛИ (ложный GAP-матч, пойман до коммита):** `Child-Pugh В 8 и` (= класс Чайлд-Пью B, балл 8,
«и») ложно матчился на шаблон `Child-Pugh classification` (GAP=`В 8 и`). Осколок из 3 символов
не может быть 14-буквенным словом. Фикс: длина рана осколков обязана согласоваться с длиной
слова шаблона (`|gap_len - len(word)| <= max(3, 0.34*len)`); `у 1 ш з`(4)~`virus`(5) — да,
`В 8 и`(3)~`classification`(14) — нет. Плюс: одно-буквенный токен шаблона (генотип `B`/`C`, код)
обязан прийти РЕАЛЬНЫМ гомографом, не «дорисоваться» из шума (иначе `С у 1 ш з` проглотил бы
различающую букву под `Hepatitis B`).

**Замер безопасности:** репарс контрольной группы I1 (КР1000_1/802_1/876_1, здоровые) + КР628_2/
957_1 -> B3a **0 правок** (нет порченых окон с чистым образцом = нет кандидатов, как гейт C5 по
построению). Регресс 117 passed / 1 skipped / 1 xfailed.

## I38. B3b рассыпанные латинские слова (промпт 17 ШАГ 2) — сигнал скринера на 96% ШУМ

**ГЛАВНЫЙ ЗАМЕР:** `shattered_latin` из `corruption_screen.py` — 2753 хита, **0 критических**,
и он на ~96% ШУМ, а не рассыпанная латиница:
- табличные числа-колонки: `0\t1\t2\t3\t4` (×292), `1\t2\t3\t4\t5` (×187);
- РАЗРЯДКА русского (letterspacing): `по д обн ы е`=подобные, `минотрансфераз ы в крови`,
  `качествен н ы е`. Это ДРУГОЙ класс (fixable_spacing, не латиница) — латинизировать его =
  порча русского (Group B);
- русские микро-фразы: `1 и 2` (×218 = «типов 1 и 2»), `А и В` (= «A and B»).

## I11. Что запрещено всегда

- Хардкод имён `КРxxx` в **продуктовом** коде. Только в тестах, фикстурах и текстах промптов.
- Смягчение порога ради возврата PASS. Если гейт топит здоровое — **чинить гейт**.
  Если топит больное — так и надо.
- «Число PASS не должно падать» как критерий приёмки. В fail-closed системе PASS **обязан**
  падать по мере честности гейтов. Правильные критерии: контрольная группа (I1) цела,
  `structured_coverage` растёт, дельта объяснима по причинам.
- Молчаливое доверие любому одному источнику: native, OCR, словарю, LLM.
- Коммит при красном регресс-наборе.
- **`git stash -u` в этом дереве — ЗАПРЕЩЁН.** `-u` сташит untracked, а тут untracked —
  это ЖИВЫЕ артефакты (`_prompts/` до коммита, `_corpus/*.py`, `scan_candidates.csv`).
  `stash drop`/`clean -fd` их стирает БЕЗ бэкапа; восстановление — только из 3-го родителя
  стэша, если повезёт. Использовать точечный `git stash push <явные файлы>` или коммит.
- **`.gitignore` НЕ поддерживает inline-комментарии.** `!__init__.py  # …` делает `#…`
  ЧАСТЬЮ паттерна, негатив не срабатывает. Комментарий — только на ОТДЕЛЬНОЙ строке.
