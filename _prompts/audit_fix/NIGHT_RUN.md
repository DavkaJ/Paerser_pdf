## ЗАДАЧА: подключить latin recovery к пайплайну и прогнать весь корпус

### ШАГ 1. Собрать все каналы починки в один резолвер
Резолвер применяется к тексту КАЖДОГО спана обучаемой зоны (sections, tables, metadata,
excluded.appendices). Порядок каналов — от дешёвого и достоверного к дорогому:

1. **A2-шаблон** (`latinnorm.py`) — гомографы БУКВ в слотах кода. `false_substitution=0`
   по построению (срабатывает только при валидной форме сущности).
2. **Гомограф ЦИФРЫ в слоте цифры** — НОВОЕ, обязательно. Грамматика сущности знает
   допустимые значения: TNM после `M` — только `0/1/x`; значит `MO` невозможно, `О`→`0`.
   Карта: `О/O→0`, `І/l/I→1`, `З→3`, `б→6`, `Ь→6`. Применять ТОЛЬКО внутри распознанного
   шаблона И только если результат валиден. Это чинит `МО→M0`, `501ЕС→S01EC`, `ТО→T0`.
3. **font-repair не-гомографов** (`fontrepair.py`) — кириллическая буква БЕЗ латинского
   двойника (`Б Г Д Ж З И Л П Ф Ц Ч Ш Щ Ъ Ы Ь Э Ю Я`) внутри латинского токена. Контур
   решает однозначно. Чинит `ВСЬС→BCLC` (Ь), `Ых→Nx` (Ы), `СНшс→Clinic` (ш).
4. **eng-OCR по кропу** — всё, что не разрешили 1–3. С ГЕЙТОМ ВАЛИДАЦИИ (см. ШАГ 2).

### ШАГ 2. Гейт валидации eng-OCR — ОБЯЗАТЕЛЕН
eng-OCR может уверенно выдать мусор (`501ЕС→SOLEC` — правдоподобное слово, не ATC-код).
Правило: **результат eng-OCR для кода-сущности принимается, ТОЛЬКО если он соответствует
форме сущности** (ATC = буква+2цифры+2буквы+цифра; МКБ = латбуква+цифры[.цифра];
TNM = T/N/M + допустимое значение). Не соответствует → `ambiguous`, НЕ применять.
Для не-кодового текста (термины, названия) гейта формы нет — там принимается, если
согласуется с font-repair-кандидатом или снижает mixed-script.

### ШАГ 3. Детектор «кириллический сирота» — НОВОЕ, закрывает дыру
Заказчик нашёл в КР628_2: `ЫазаШ→Nasal`, `ТетрогаШ→Temporal`, `1п[епог→Inferior`,
`хап→van`, `8рае1И→Spaeth`. Это ПОЛНОСТЬЮ кириллические (или почти) токены, которые на
самом деле латинские слова — существующий mixed-script детектор их НЕ видит.
Добавить детектор нарушения русской орфографии (дёшево, высокий recall):
- токен начинается с `Ы`, `Ь`, `Ъ` — невозможно в русском;
- заглавная буква ВНУТРИ токена (`ЫазаШ`, `ТетрогаШ`);
- цифра внутри буквенного токена (`1п[епог`, `8рае1И`);
- скобка/слэш внутри токена (`[епог`, `8Иа//ег`).
Такой токен → подозрительный → font-repair, затем eng-OCR. Провенанс обязателен.

### ШАГ 4. Символ `□` (U+25A1) и подобные unmapped-глифы
Глиф без сопоставления в шрифте. Попытаться восстановить eng-OCR по его bbox; если OCR
тоже пусто — удалить символ (не тащить в корпус). Записать в провенанс как `unmapped`.

### ШАГ 5. Провенанс — ЖЁСТКО
Каждая замена, любым каналом → запись в блоке `latin_recovery` выходного JSON:
`{span_uid, page, source_text, resolved_text, method, rule, confidence}`.
**Молчаливых замен быть НЕ может.** Мы это проходили: пин `рб1→PDI` молча закрепил ошибку
на весь корпус. Правка без записи в провенанс = необратима и недоказуема = запрещена.

### ШАГ 5-bis. ОЧЕРЕДЬ ВЕРИФИКАЦИИ — то, что утром откроют в Label Studio
Это ядро ночной работы для человека. Каждая замена делится на ДВЕ категории:

**УВЕРЕННАЯ** (`confidence` высокая, форма сущности валидна, каналы согласны) — применяется
молча (но с провенансом). Человеку смотреть не обязательно.

**НЕУВЕРЕННАЯ** — применяется ЛУЧШИЙ кандидат, НО спан помечается `needs_review: true` и
попадает в очередь. Критерии неуверенности:
- eng-OCR без подтверждения формой сущности (не-кодовый текст);
- несколько правдоподобных кандидатов разошлись;
- цифро-гомограф вне явного шаблона;
- критическая сущность (ATC/МКБ/TNM/доза/препарат/ген), восстановленная OCR, а не A2-шаблоном;
- `□` и unmapped-глифы.

Сложить всё неуверенное в `_corpus/verify_queue/`:
- `tasks.json` — список задач в формате импорта Label Studio. Каждая задача:
  `{doc, span_uid, page, bbox, crop_png, source_text, resolved_text, candidates[],
    method, confidence, entity_kind, why_uncertain}`;
- `crops/` — PNG-кроп каждого спорного места (рендер bbox из PDF, ~400 DPI, чтобы человек
  глазами прочитал что там написано). Механизм рендера кропа уже есть: `ocr.py:_clip_text`
  использует `_render(page, clip)` — переиспользуй его для сохранения PNG;
- `labeling_config.xml` — конфиг Label Studio: показывает crop_png + исходный текст +
  список кандидатов, кнопки «принять / выбрать другой / ввести свой / исходник верен /
  неразборчиво / нужен медэксперт».

**Цель: утром человек открывает Label Studio, видит очередь спорных мест с картинками и
быстро подтверждает/правит.** Чем больше уверенных автозамен и чем точнее очередь — тем
меньше ручной работы. Но НЕ перекладывай уверенное в очередь ради подстраховки: очередь
должна содержать реально спорное, иначе человек утонет.

Замерить и доложить: сколько замен уверенных (авто) / сколько в очереди / из них критических.

## Правила автономного решения (не спрашивать)
- **Порог/дельта.** PASS может падать — норма (I11). Проверь I1, разложи дельту, иди дальше.
- **Канал не сработал** (font-repair не восстановил, OCR пусто) → спан → `ambiguous`,

  ВАЛИДНЫЙ исход, не провал.
- **Тест группы A красный** → чинить механизм (это несделанная работа), перепрогон, не
  ослаблять тест. До зелёного.
- **Тест группы B/C красный** → это регресс, чинить немедленно, НЕ коммитить.
- **Не строить Label Studio / LLM.** Разметка людьми — промпт 14, ночью недоступна.
  Достаточно A2 + digit-slot + font-repair + eng-OCR + release-gate.

## Три аварии — когда (и ТОЛЬКО когда) остановиться
Это НЕ плановые точки. Это три ситуации, когда продолжать физически нельзя или опасно.
За всю предыдущую работу (11 промптов) ни одна не сработала. Если сработала — значит
что-то пошло по-крупному не так, и молча продолжать = навредить.

- **E1 — ломаешь здоровое.** Контрольная группа I1 (6 файлов) ушла из PASS и не чинится
  за 2 попытки. Продолжать = уверенно портить хороший текст.
- **E2 — теряешь контент.** `owned_before ⊄ owned_after` (спан исчез без владельца) ИЛИ
  вычтенный текст не покрыт ничьим `raw_text`. Это ровно то, ради чего весь проект.
- **E3 — нужны деньги/люди/железо.** GPU, платная модель, наём разметчиков, слом схемы,
  перезаливка коллегам. Ночью ты этого не достанешь.

**Во всех остальных случаях — НЕ останавливаешься.** Не уверен → пометь `needs_review` и
дальше. Канал не сработал → `ambiguous` + карантин и дальше. Тест группы A красный → чини
и дальше. PASS упал → норма, дальше.

Если авария реально наступила: стоп, подробный отчёт в `_corpus/NIGHT_BLOCKED.md`
(что, где, почему нельзя продолжить), и **продолжай работу над ОСТАЛЬНЫМ**, что не задето
аварией. Не сиди без дела — авария в одном канале не блокирует другие.
