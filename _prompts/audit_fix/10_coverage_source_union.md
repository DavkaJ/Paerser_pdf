# 10. Coverage v2: честные метрики по span-union вместо бухгалтерии символов

> **Редакция 2.** Первая редакция содержала формулу `structured_coverage = |A| / |S \ B_expected|`,
> которая **может дать больше 1**, если A пересекается с исключёнными строками. Исправлено.
> Кроме того, она относила приложения к «легитимно исключённому», тогда как промпт 04 считал
> их телом, а контракт 06 вырезал весь `excluded`. Противоречие разрешено: **приложения —
> обучающий контент** (там шкалы Child-Pugh, ECOG, Karnofsky и критерии качества).

**Доказательства из кода (проверены, `stats.py`).**

- `accounted_raw = included_chars + excluded_chars + table_chars` — складываются **длины**.
- `accounted_chars = min(accounted_raw, total_chars)` — переполнение **молча обрезается**.

Текст, попавший **не в тот раздел**, свалившийся в `excluded.other` или **продублированный**
между buckets, — считается «покрытым».

**Живые доказательства:** `КР848_1` — 13 879 + 44 011 + 3 661 = **61 551** при total
**54 047** (+13,9%), обрезано до `coverage = 100.0`, при ОДНОЙ секции. `КР809_1` — 175 807
против 171 506 (+2,51%). `КР675_2` — coverage 100 при MISSING 3.3–3.4.2. `КР284_2` —
coverage 100 при потере четырёх разделов. `КР839_1` — coverage 100 при потере глав 4 и 5.

## Разбиение span'ов: три класса, не два

Пусть S — все `span_uid` документа (из промпта 08).

| Класс | Что входит | Роль |
|---|---|---|
| **TRAINING** | sections ∪ tables ∪ **excluded.appendices** | то, ради чего всё делается |
| **NON_TRAINING** | excluded.toc ∪ excluded.front_matter ∪ excluded.references | законно вне обучения (контракт 06) |
| **GARBAGE** | excluded.other | мусорная корзина сегментера |

`excluded.other` — **не** легитимное исключение. Это признак того, что сегментер не понял
документ, и его нельзя списывать в знаменатель как «так и задумано».

```
Задача: coverage начинает измерять сохранность СТРУКТУРЫ, а не бухгалтерию символов.
Требует промптов 08 (span_uids ВЕЗДЕ, включая excluded) и 09 (честный subtraction).
Правки в stats.py и validate.py. Схема — аддитивно.

=== МЕТРИКИ (все по span_uid, не по длинам строк) ===
  S            = все span_uid документа
  T            = union(span_uids: sections ∪ tables ∪ excluded.appendices)   # TRAINING
  N            = union(span_uids: excluded.toc ∪ front_matter ∪ references)  # NON_TRAINING
  G            = union(span_uids: excluded.other)                            # GARBAGE
  D            = S \ N        # знаменатель структурности: всё, что ДОЛЖНО было лечь в структуру

1. `source_retention` = |T ∪ N ∪ G| / |S|
   Сколько исходных span'ов вообще где-то сохранилось. Отвечает: «что мы физически потеряли».
   ВАЖНО: для синтетики «1 символ в section + 99 в excluded» эта метрика = 100%,
   и это ПРАВИЛЬНО — ничего не потеряно. Ревью справедливо поправило первую редакцию,
   где я объявлял 100% дефектом. Дефект — не здесь.

2. `structured_coverage` = |T ∩ D| / |D|
   **Исправленная формула.** Пересечение обязательно: без него метрика может превысить 1,
   если T захватил span'ы из N.
   Отвечает: «сколько содержательного текста легло в структуру». **Главная метрика.**
   Для той же синтетики она даст ~1% — вот где виден дефект.
   У КР848_1 обязана быть катастрофически низкой при нынешнем `coverage_percent = 100`.

3. `garbage_ratio` = |G| / |S|
   Мусорная корзина. У КР848_1: 834 элемента в `other` -> метрика обязана быть большой.

4. `overlap_spans` = span'ы, у которых БОЛЕЕ ОДНОГО владельца (секция+таблица,
   секция+excluded, две секции). Плюс `overlap_chars` — их суммарная длина.
   **Это ровно то дублирование, что сейчас прячется под `min()`.**
   У КР628_2 обязано быть > 0 (аудит §4.2: «Критерии качества» в sections[6].text И в
   tables[1]/[2]).

5. `lost_spans` = |S \ (T ∪ N ∪ G)| — не сохранилось нигде. Число — в stats, первые 20
   span_uid — в warnings. Впервые доказуемый список потерянного.

6. `overcount_ratio` = (included_chars + excluded_chars + table_chars) / total_chars
   Старая арифметика, но БЕЗ обрезки. У КР848_1 = 1.139, у КР809_1 = 1.025.

=== СОВМЕСТИМОСТЬ ===
`coverage_percent` вычисляется ПО-ПРЕЖНЕМУ, той же формулой, с тем же `min()`. Не трогать —
downstream его читает. В схеме пометить `deprecated`.
Новый блок:
    "coverage_v2": {
      "source_retention": 0.98, "structured_coverage": 0.41, "garbage_ratio": 0.33,
      "overlap_spans": 87, "overlap_chars": 4210, "lost_spans": 12,
      "overcount_ratio": 1.139, "total_spans": 1840
    }

=== ВАЛИДАТОР (validate.py) ===
Гейты поверх coverage_v2. **Пороги НЕ брать из головы.** Порядок обязателен:
  1. посчитать распределение всех шести метрик по 722 файлам;
  2. напечатать перцентили p10/p50/p90/p99;
  3. показать: «при пороге X из PASS уходит N файлов, вот 5 примеров»;
  4. только потом фиксировать константы.
Стартовые гипотезы (не догма):
  - `structured_coverage < 0.70` -> REVIEW (LOW_STRUCTURED_COVERAGE)
  - `garbage_ratio > 0.30` -> REVIEW (HIGH_GARBAGE)
  - `overlap_spans > 0` -> REVIEW (DUPLICATION). Дублирование в обучающем корпусе — не
    косметика: модель увидит один фрагмент дважды в разных контекстах.
  - `overcount_ratio > 1.02` -> REVIEW (OVERCOUNT)
  - `lost_spans / total_spans > 0.02` -> REVIEW (LOST_CONTENT); >0 -> warning

**Статус порогов:** это triage-гейты, не доказательство release readiness. До промпта 14
они не аттестуют ничего. После — перекалибровать на gold-dev, проверить на holdout.
```
