# 03. Валидатор fail-closed: schema, честный exit, пересчёт stats, римское оглавление

**Доказательства из кода (проверены построчно).**

- `validate.py`, `Report.ok`: `return not self.fails and self.skipped is None` — **reviews
  игнорируются**. `Report.status` при этом честно отдаёт `REVIEW`.
- `validate.py`, CLI-хвост: `npass = sum(1 for r in judged if r.ok)`, затем
  `return 0 if npass == len(judged) else 1`. Поскольку у REVIEW `ok == True`, **корпус из
  одних REVIEW даёт exit 0.** Это и есть fail-open.
- `validate.py:_NUM_RE = re.compile(r"^\d+(\.\d+)*$")`, а `Toc.numbered()` фильтрует записи
  оглавления по нему. **Римские номера (`XII.`, `XIII.`) отбрасываются целиком.**
  Прямое следствие: у `КР848_1` оглавление содержит 29 римских записей, `numbered()` даёт
  пустой список, MISSING не выставляется — файл получает **PASS без единого warning**,
  имея ОДНУ секцию на весь документ.
- Валидатор доверяет `stats` из выходного JSON (`stats = doc.get("stats", {})`). Подделанные
  или ошибочно посчитанные stats никем не перепроверяются.
- Сериализация (`jsonio.py`) — это не валидация схемы. Пустой `{}` трактуется как скан.

Задача: валидатор перестаёт быть fail-open. Четыре правки, только validate.py

=== ПРАВКА 1. JSON Schema, fail-closed ===
- Новый файл `crparser/data/cr_schema.json` — JSON Schema (draft 2020-12) выходного
  документа: metadata / sections (рекурсивно) / tables / excluded / stats / warnings.
  Обязательные поля и типы — по фактической схеме, БЕЗ ужесточения (схема описывает то,
  что есть, а не то, что хотелось бы).
- В validate_doc: первым делом валидировать doc по схеме. Несоответствие -> `rep.fail(
  "SCHEMA", ...)`. НЕ REVIEW, а FAIL: файл, не соответствующий контракту, не может быть
  выпущен ни при каких обстоятельствах.
- Пустой `{}` -> SCHEMA FAIL, а не SKIP. Скан определяется ТОЛЬКО через
  `stats.total_chars < 200` при валидной схеме.
- Зависимость: `jsonschema`. Если её нет в окружении — добавить в требования; при
  отсутствии библиотеки валидатор должен ПАДАТЬ, а не пропускать проверку.

=== ПРАВКА 2. Честные ok / status / exit ===
- `Report.ok` -> `return not self.fails and not self.reviews and self.skipped is None`.
- CLI: exit 0 ТОЛЬКО если каждый обработанный файл имеет status == "PASS".
  REVIEW, FAIL, SCHEMA, а также SKIP при непустом текстовом слое -> ненулевой exit.
- SKIPPED_SCAN (реально пустой текстовый слой) не считать успехом: он не PASS, он
  «не обработан». В итоговой строке печатать три числа раздельно и возвращать exit 1,
  если есть хоть один не-PASS. Отдельный флаг `--allow-review` может смягчать поведение
  для локальной отладки, но по умолчанию его НЕТ.

=== ПРАВКА 3. Stats пересчитываются, а не принимаются на веру ===
- Валидатор пересчитывает из самого doc: sections_found (обход дерева), included_chars,
  excluded_chars, table_chars, total_chars брать НЕЛЬЗЯ из doc (его нет в выходе иначе) —
  поэтому: сверять пересчитанные значения с заявленными в `doc["stats"]`.
- Расхождение любого счётчика -> `rep.fail("STATS_MISMATCH", "<поле>: заявлено X, факт Y")`.
- Отдельно: `coverage_percent` вне [0, 100], NaN, None -> FAIL.
- Отдельно: `included + excluded + tables > total_chars` -> `rep.review("OVERCOUNT",
  "сумма учтённого превышает источник на N символов — дубли между buckets")`.
  Проверено: у КР848_1 сумма 61 551 при total 54 047 (превышение 13,9%), у КР809_1 —
  175 807 против 171 506 (превышение 2,51%). Это ровно тот случай, который сейчас
  прячется под `min(accounted_raw, total_chars)`.
  Порог: OVERCOUNT_MIN = 1.02 (превышение >2%). Ниже — шум округления подписей таблиц.

=== ПРАВКА 4. Оглавление: римская нумерация ===
- `_NUM_RE` расширить или дополнить вторым паттерном: римские номера верхнего уровня
  (`I`–`XXX`, с точкой или без), в т.ч. смешанные (`XII.1`).
- `Toc.numbered()` должен возвращать И арабские, И римские записи; сверка «номер рядом с
  заголовком в теле» (`body_has_numbered`) должна работать для обоих.
- Нормализация: `I`/`1` и `Х`(кириллическая)/`X`(латинская) — типовая порча источника.
  Сравнение вести по нормализованной форме (кириллические гомографы римских цифр
  приводить к латинским: Х->X, У->Y, С->C, І->I, Ѵ->V).
- Если оглавление НЕ распознано (`parse_toc` вернул None) или распознано пустым —
  это НЕ повод для PASS: `rep.review("TOC_NONE", ...)`. Сейчас такой файл молча
  проходит структурную сверку «ни с чем».

- Корпусный прогон: exit != 0 (в корпусе гарантированно есть REVIEW и FAIL).

- Ожидаемая дельта: PASS падает с 616 примерно до 590-610 (римские TOC + OVERCOUNT +
