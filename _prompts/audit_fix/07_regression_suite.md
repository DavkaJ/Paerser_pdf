# 07. Регресс-набор: каждая закрытая дыра получает тест

**Зачем.** Аудит, §3.5 п.9, перечисляет ровно те тесты, которых нет. Без них следующий
«локальный фикс» тихо откроет любую из дыр обратно — что уже происходило (fail-open PASS
пережил несколько итераций правок валидатора).

Это последний промпт фазы B. После него **ни один промпт не коммитит на красном наборе**.

```
Задача: собрать регресс-набор, покрывающий каждую дыру из аудита. Тесты — быстрые,
без обращения к 722 PDF. Фикстуры — синтетические dict'ы и 5-8 маленьких PDF.
Продуктовый код НЕ трогать (кроме случая, когда тест нашёл настоящий баг — тогда
доложить и остановиться, фикс отдельным промптом).

=== СТРУКТУРА ===
tests/
  fixtures/docs/      — синтетические JSON-документы (dict) для валидатора
  fixtures/pdfs/      — минимальные PDF (уже есть tests/pdfs — переиспользовать)
  test_validator_gates.py
  test_batch_transaction.py
  test_stats.py
  test_tables.py
  test_ocr_pins.py
  test_schema.py
Прогон: `python -m pytest tests/ -q`. Добавить pytest в требования.

=== ГРУППА 1. Валидатор (закрывает 03/04) ===
1.  Пустой `{}` -> SCHEMA FAIL, exit != 0. (Было: SKIP, exit 0.)
2.  Документ с валидной схемой, но `stats.coverage_percent = 100` при фактическом 40 ->
    STATS_MISMATCH FAIL. («Forged stats».)
3.  `coverage_percent` = -1 / 101 / NaN / null -> FAIL по каждому.
4.  Один мусорный узел: sections = [{number: null, title: "XII. …", text: "<40k символов,
    начинается с 'XIII. Список литературы'>"}], excluded.other = 834 элемента,
    included+excluded+tables > total -> НЕ PASS. Ожидаем COLLAPSE + OVERCOUNT.
    (Это модель КР848_1, дословно.)
5.  Оглавление с римскими номерами (XII., XIII.) и пустым списком арабских -> MISSING
    выставляется, файл НЕ PASS. (Раньше `_NUM_RE` их не видел вовсе.)
6.  parse_toc вернул None -> TOC_NONE REVIEW, НЕ PASS.
7.  Оглавление распознано, но пустое -> TOC_NONE REVIEW.
8.  Три секции при total_chars = 120 000 -> COLLAPSE REVIEW. (Модель КР401_2.)
9.  Одна секция держит 78% included_chars при 7 секциях -> COLLAPSE REVIEW.
    (Модель КР973_1.)
10. `stats.corruption.pseudo_ascii_tokens = 1` -> OCR_REQUIRED REVIEW, НЕ PASS.
    (Модель КР396_4.)
11. Текст секции содержит ключ из активной базы пинов (напр. «Вагсе1опа») ->
    RESIDUAL_PIN REVIEW. Тот же ключ ТОЛЬКО в excluded.references -> warning, не REVIEW.
12. Здоровый документ (7 канонических глав, чистый текст, 66 легитимных латинских
    токенов, 0 §-токенов) -> PASS. **Это главный анти-регресс-тест: гейты не должны
    топить здоровое.** Собрать фикстуру из реального КР1000_1.
13. Корпус из одних REVIEW -> CLI возвращает НЕнулевой exit. (Было: 0.)

=== ГРУППА 2. Батч-транзакционность (закрывает 05) ===
14. Сбой записи одного документа -> его статус FAIL(WRITE_FAILED), публикации нет,
    старый outout/ не изменён, exit != 0.
15. CRASH при парсинге -> старый JSON этого документа НЕ переживает публикацию.
16. Множество результатов != expected -> публикации нет, exit != 0.
17. ocr_pins.json изменился в ходе прогона -> прогон падает.
18. Частичный прогон одного файла не удаляет остальные.

=== ГРУППА 3. Stats / coverage (закрывает 10, тест пишем СЕЙЧАС — он должен падать) ===
19. Синтетика: total_chars = 100, один символ в sections, 99 символов в excluded.
    Текущее поведение: coverage = 100%. **Тест фиксирует это как ИЗВЕСТНЫЙ ДЕФЕКТ**
    (`pytest.mark.xfail(strict=True)` с внятным reason). Промпт 10 обязан снять xfail.
20. Дублирование одного и того же текста между sections и tables -> `overlap_chars` > 0
    (после 10). Сейчас — xfail.

=== ГРУППА 4. Таблицы (закрывает 09, часть тестов — xfail до промпта 09) ===
21. PDF со СМЕШАННЫМИ таблицами (одна рамочная + одна безрамочная) -> найдены ОБЕ.
    Сейчас: whitespace-fallback стоит под `if not tables:` на уровне ДОКУМЕНТА, поэтому
    безрамочная теряется. xfail(strict=True) до промпта 09.
22. Таблица, чей `_dump_text` вернул пустую строку -> её bbox НЕ попадает в
    subtraction_map (текст не должен исчезать из тела). xfail до 09.
23. Многостраничная таблица -> строки со второй страницы не потеряны. xfail до 09.

=== ГРУППА 5. Пины/кэш (закрывает 02) ===
24. Прогон НЕ изменяет sha256 файла crparser/data/ocr_pins.json.
25. Новые пары уходят в _corpus/pins_proposed_*.json, а не в базу.
26. Ключ кэша меняется при смене версии Tesseract / traineddata / Pillow / DPI /
    содержимого PDF. Одинаковое имя файла при разном содержимом -> РАЗНЫЕ ключи кэша.
27. В активной базе пинов нет пары с целевым значением `PDI`.

=== ГРУППА 6. Схема (закрывает 03) ===
28. Все 722 текущих JSON валидируются против cr_schema.json. Любой невалидный —
    назвать поимённо. (Ожидается: все валидны; если нет — это находка, доложить.)

=== ГРАНИЦЫ ===
- Тесты не должны требовать Tesseract/GPU. Всё, что зависит от OCR, — мокать.
- Тесты не читают 722 PDF. Максимум — 8 фикстур.
- xfail(strict=True) обязателен для дефектов, которые чинят промпты 09 и 10: strict
  гарантирует, что тест ПАДЁТ, если дефект внезапно «починился» сам, — и мы это заметим.
- Не менять продуктовый код. Тест, нашедший новый баг, — повод доложить, а не чинить на месте.

=== ТЕСТЫ-ПИНЫ (метатесты) ===
- `pytest tests/ -q` проходит целиком (xfail считаются ожидаемыми).
- Ни один тест не занимает > 5 секунд.
- Откат промпта 03 (вернуть старый `Report.ok`) -> красными становятся тесты 1, 13.
  Откат промпта 04 -> красными 4, 8, 9, 10, 11. Проверить это руками: набор обязан
  ЛОВИТЬ регресс, а не просто существовать.
```
