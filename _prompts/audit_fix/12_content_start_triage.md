# 12. Content-start: разделить три root cause вместо одного глобального порога

**Позиция аудита, с которой я согласен.** Решение «не менять глобальный threshold
`_find_content_start` из-за риска регресса на 700 файлах» — **верное**. Ошибка была не в
этом, а в том, что известно дефектные файлы остались в общей публикуемой директории.
Карантин уже введён промптом 06. Теперь можно чинить причины — по одной, безопасно.

**Аудит доказал, что «~16 обвалов» — это НЕ один класс бага, а минимум три:**

1. **start внутри TOC** — `КР715_2`, `КР675_2`: тело «начинается» посреди оглавления.
2. **start в glossary/front matter** — `КР891_1`, `КР115_2`, `КР467_3`: тело «начинается»
   в списке сокращений или терминах.
3. **несовместимая numbering model при КОРРЕКТНОМ старте** — `КР284_2`, `КР750_1`: старт
   найден верно, но модель нумерации документа не та, что ожидает профиль.

Один порог не может починить три причины. Более того, тюнинг порога под класс 1 почти
наверняка ухудшит класс 3.

```
Задача: разложить обвалы content-start по причинам, починить КАЖДУЮ отдельным механизмом,
подтвердить нулевой регресс на здоровых. Требует промптов 06 (карантин), 07 (регресс),
11 (ContentBoundaryPolicy — код едет туда, а не в segmenter).

=== ШАГ 1. Классификатор причин (диагностика, НЕ фикс) ===
Скрипт `_corpus/diag_content_start.py`: для КАЖДОГО файла корпуса определить, где парсер
поставил начало тела, и классифицировать:
  - START_IN_TOC: точка старта попадает в регион оглавления (регион известен сегментеру);
  - START_IN_FRONTMATTER: старт в списке сокращений / терминах / титульных данных;
  - NUMBERING_MISMATCH: старт корректен, но <5/7 канонических глав распознано;
  - OK.
Вывод: `_corpus/content_start_classes.json` + таблица «класс -> число файлов -> примеры».
Ожидается ~16 не-OK. **Если их сильно больше или меньше — сначала разобраться, почему
расходится с оценкой аудита, и только потом чинить.**

=== ШАГ 2. Класс START_IN_TOC ===
Причина: детектор тела принимает строку оглавления за заголовок раздела (у неё тот же
номер и то же название — по определению).
Фикс: тело НЕ МОЖЕТ начинаться внутри региона, уже размеченного как TOC. Регион оглавления
определяется ДО поиска content-start (он уже определяется — `toc_bounds`). Сделать это
жёстким инвариантом: `content_start > toc_region.end`.
Если после этого содержательного текста не остаётся — это не «нашли тело», это FAIL/REVIEW.
Эталоны: КР715_2, КР675_2.

=== ШАГ 3. Класс START_IN_FRONTMATTER ===
Причина: список сокращений и «Термины и определения» структурно похожи на разделы.
Фикс: front-matter регионы (сокращения, термины, состав рабочей группы, конфликт интересов)
размечаются ЯВНО через `RegionPolicy` (промпт 11) и исключаются из зоны поиска
content-start ровно так же, как TOC.
Важно: аудит §4.1/§4.2 отдельно зафиксировал, что `excluded.toc[0].text` СКЛЕИВАЕТ
оглавление + сокращения + термины в один элемент (КР1_4: pp3-7; КР628_2: pp2-6).
**Разделить их на отдельные excluded-элементы с корректными границами** — это часть фикса,
а не косметика: без разделения нельзя исключить только front matter, не выбросив TOC.
Эталоны: КР891_1, КР115_2, КР467_3.

=== ШАГ 4. Класс NUMBERING_MISMATCH ===
Причина: документ использует модель нумерации, не покрытую профилем (римские главы,
локальные подпункты, глубокая вложенность, inline-split за пределами глав 1-7).
Фикс — в `NumberingPolicy` (промпт 11), НЕ через порог:
  - профиль пробует НЕСКОЛЬКО моделей нумерации и выбирает ту, что даёт наибольший
    канонический recall при сверке с оглавлением;
  - если ни одна не даёт recall >= 5/7 -> документ уходит в карантин с
    kind="NUMBERING_MISMATCH". Мы НЕ угадываем.
  - снять частные ограничения, найденные аудитом: inline-split только для глав 1-7
    (`clinical.py`), «одиночный арабский номер всегда level 1», отключение римских глав
    целиком при появлении локальных 1,2,3.
  - `NUMBER_ONLY`-заголовок, который не приклеился, СЕЙЧАС потребляется и теряется
    (`segmenter.py`). Он не должен теряться: не приклеился -> остаётся в тексте.
Эталоны: КР284_2, КР750_1.

=== ШАГ 5. Каноничность заголовка: убрать startswith и слабые сигналы промоушена ===
Отдельный класс хрупкости, зафиксированный аудитом §1.4 (третий буллет) и подтверждённый
в коде: `clinical.py`, `_valid_main_title` сверяет каноничность через `low.startswith(prefix)`.
Префиксное сравнение принимает за каноническую главу любую строку, СЛУЧАЙНО начинающуюся
так же (пункт списка, строка таблицы, кросс-ссылка). Рядом — эвристики промоушена
заголовка по слабым сигналам (visual / uppercase / lexical), способные поднять в заголовок
обычную строку.
Фикс:
  - каноничность — по НОРМАЛИЗОВАННОМУ ПОЛНОМУ совпадению с канонической формой (с учётом
    допустимых вариантов написания), а не по префиксу. Список канонических форм — в
    `NumberingPolicy`/профиле (промпт 11);
  - промоушен по слабым сигналам разрешён ТОЛЬКО при совпадении с ожидаемым по оглавлению
    номером/названием. Слабый сигнал сам по себе заголовок не создаёт.
Регресс жёсткий: это трогает ВСЕ 722 файла. После фикса — обязательный `manifest --verify`;
изменившиеся файлы разобрать поимённо. Если изменилось больше ~30 — фикс слишком широк.

=== ГРАНИЦЫ ===
- Каждый класс чинится ОТДЕЛЬНЫМ коммитом, с отдельным замером регресса. Не смешивать.
- После КАЖДОГО класса: `manifest --verify` + report.json. Число изменившихся файлов
  обязано быть СОПОСТАВИМО с числом файлов этого класса. Если фикс класса START_IN_TOC
  (2 файла) изменил 200 JSON — он трогает здоровые, откатывать.
- Никаких списков имён КРxxx в коде.
- Не «дотягивать» файл до PASS любой ценой. Честный карантин лучше угаданной структуры.

=== ТЕСТЫ-ПИНЫ ===
- КР715_2, КР675_2: content_start больше не внутри TOC; структура восстанавливается ИЛИ
  файл честно уходит в карантин с внятной причиной.
- КР891_1, КР115_2, КР467_3: тело не начинается в глоссарии.
- КР284_2: 4 потерянных раздела возвращаются ЛИБО файл получает NUMBERING_MISMATCH.
  (Сейчас: coverage 100% при потере четырёх разделов — худший из возможных исходов.)
- КР1_4: `excluded.toc` больше не склеивает pp3-7 в один элемент — оглавление,
  сокращения и термины разделены. То же для КР628_2 (pp2-6).
- КР848_1: римская нумерация распознаётся, документ получает структуру ИЛИ честный
  NUMBERING_MISMATCH — но НЕ одну секцию с coverage 100%.
- РЕГРЕССИЯ (жёстко): 4 здоровых эталона (КР802_1, КР845_1, КР901_1, КР1000_1) —
  байт-в-байт без изменений после КАЖДОГО из трёх фиксов.
- Суммарно по корпусу: число файлов класса OK в `content_start_classes.json` **растёт**.
  **Требование «число PASS не падает» СНЯТО** — оно противоречит fail-closed системе.
  В системе с честными гейтами PASS может законно упасть: файл, у которого мы наконец
  правильно нашли начало тела, может обнажить дефекты, которых раньше просто не видели.
  Правильный критерий: растёт `structured_coverage` (промпт 10) и падает число файлов
  в карантине по причинам START_IN_TOC / START_IN_FRONTMATTER. Динамику PASS
  **докладывать**, но не использовать как гейт.

=== ДЕРЕВО РЕШЕНИЙ — идти самостоятельно ===

**Р1. Каждый класс — отдельный коммит и отдельный замер.** Не смешивать. Если фикс класса
START_IN_TOC (2 файла) изменил >30 JSON — он трогает здоровые, **откатывать и сужать**.

**Р2. Файл не поддался фиксу → карантин, не подгонка.**
Не «дотягивать» документ до PASS. Честный `NUMBERING_MISMATCH` в карантине лучше угаданной
структуры в обучающем корпусе. Это валидный исход, не провал.

**Р3. Контрольная группа I1 — байт-в-байт после КАЖДОГО из трёх фиксов.**
Сломалась и не чинится за две попытки → **E1, стоп**.

**Р4. `startswith`-каноничность (шаг 5) трогает ВСЕ 722.**
Ожидаемая дельта — до ~30 файлов. Больше → фикс слишком широк, сузить.
- КР848_1 обязан остаться не-PASS.
- КР66_4/КР876_1 (римские) обязаны остаться PASS.

**Р5. PASS может упасть — это норма** (I11). Правильные критерии: I1 цела,
`structured_coverage` растёт, число файлов класса OK в `content_start_classes.json` растёт.
Не подгонять PASS.

=== РЕГЛАМЕНТ ===
1. Шаг 1 (диагностика) — отдельный коммит, без фиксов.
2. Шаги 2/3/4/5 — отдельные коммиты, каждый со своим замером регресса и проверкой I1.
3. Что не поддалось — в карантин с причиной.
4. Дописать находки в INVARIANTS.
5. Коммиты: «Content-start: тело не начинается внутри оглавления» / «…внутри front
   matter» / «Нумерация: выбор модели по каноническому recall вместо угадывания» /
   «Каноничность заголовка: полное совпадение вместо префикса».
6. **Сразу переходить к промпту 13.**
```
