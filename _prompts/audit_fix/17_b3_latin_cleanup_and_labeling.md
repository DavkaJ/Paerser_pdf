## ШАГ 0 (БЛОКЕР — до любой регенерации корпуса). OCR/rus: доказать гейт, зафиксировать политику.
Найдено Cowork-ревью: на машине прогона НЕТ `rus.traineddata` (`tesseract --list-langs` = eng,osd),
а базовый гибрид-проход `OcrRecoverer(langs="rus+eng")` его требует; `disagreements=486` у КР1_4
отдаёт КЭШ, не живой OCR. Пока не закрыто — регенерация корпуса невалидна.
1. **Доказать гейт исполнением:** на машине без rus запустить batch — убедиться, что
   `OcrRecoverer.available()==False` → `--require-ocr` даёт exit 2, публикации нет. Если
   публикация ПРОШЛА (как в инциденте `ac5d03a`) — это открытая fail-open дыра, чинить ПЕРВОЙ.
2. **Зафиксировать политику OCR** (осознанно, в INVARIANTS):
   - латинский кроп-канал — `eng` (решение верное, 13b: rus+eng читал латиницу кириллицей);
   - базовый гибрид-проход — нужен `rus` ТОЛЬКО для сканов (нет текстового слоя, русское тело).
     Решить: (а) поставить `rus.traineddata` на машину прогона; ИЛИ (б) для born-digital идти
     `OCR_LANGS=eng` + native + font-repair, а сканы — отдельным маршрутом с rus; ИЛИ (в) явно
     работать из кэша со 100%-проверкой покрытия. Выбор записать с обоснованием.
3. **Уточнить I34:** корень инцидента — отсутствие языковых данных `rus` (+ TESSDATA), а НЕ
   «`_resolve_tesseract` вернул None» (бинарь есть на PATH). «Выставить TESSERACT_CMD» рецидив
   не предотвращает.
**Пока ШАГ 0 не зелёный — ШАГИ 4–6 (регенерация) НЕ запускать.** ШАГИ 1–3 (код за флагом,
юнит-тесты на фикстурах) писать можно параллельно.

## ШАГ 1. B3a — внутридокументный self-repair (детерминизм, без OCR/моделей). ГЛАВНОЕ для §2.3.
Если якорное слово (напр. `Hepatitis`) в одном месте битое, а в ЭТОМ ЖЕ документе есть чистая
форма той же фразы — чинить битое по чистому образцу. Замерено: `Hepatitis C virus` в КР1_4 §2.3
встречается 5×, чист 3× → 2 битых (`Hepatitis В virus`, `Hepatitis С у 1 ш з`) чинятся
консистентностью, и гомограф `С`, и шаттер `у 1 ш з` разом. Алгоритм: собрать чистые
латинские/смешанные фразы-якоря по документу; для подозрительного участка (флаг скринера) найти
выравниваемый чистый образец той же фразы; заменить по образцу. Провенанс `intra_doc_selfrepair`,
`decision=auto` только при уверенном выравнивании, иначе needs_review. **Фикстура (тест, НЕ пин):**
перепарс КР1_4 с OCR ON → `Hepatitis C virus` чист во ВСЕХ 5 вхождениях; `у 1 ш з` отсутствует.

## ШАГ 2. B3b — run-level детектор рассыпанных слов → ШИРОКИЙ кроп eng-OCR.
Источник флагов — `shattered_latin` из `_corpus/corruption_screen.py` (уже ловит `у 1 ш з`:
run ≥2 одно-символьных кир/цифро-токенов рядом с латиницей / с hard-буквой). У рассыпанного
слова НЕТ границ для узкого кропа → OCR по кропу ВСЕЙ строки/фразы (`_clip_text`, широкий bbox,
`langs='eng'`). Это ПРОТИВОПОЛОЖНО B1 (там узкий кроп). Ширину кропа выбирать по типу порчи.
Неуверенно → needs_review + карантин.

## ШАГ 3. B3c — гомограф в латинском окружении.
Одиночная кир-буква между латинскими токенами (`Hepatitis С virus`) — почти наверняка латинский
гомограф. Снять freq-защиту ТОЛЬКО для случая «одна кир-буква, слева и справа латиница». Не
трогать одиночные кир-буквы в русском окружении.

## ШАГ 4. Поднять авто-долю (меньше в очередь) + арбитр (модели подняты).
- **B1 пословный кроп (I30 #4):** eng-OCR по кропу ЦЕЛЕВОГО слова для подтверждения гомографа;
  честно перемерить авто-долю (факт, не оценка).

## ШАГ 6. Минимизировать очередь → готовность к Label Studio. ЭТО ФИНАЛ ДЛЯ ЧЕЛОВЕКА.
Сейчас очередь = 8872 задачи (6634 уникальных форм, 1379 критических уникальных) + ШУМ
(`почти`, `со2`, `000`, одиночные `ь/ы`). Человеку это грести нельзя. Сделать:
1. **Авто-разрешённое (auto) убрать из очереди** — B3/B1/B2/арбитр уже почистили; в очереди
   остаётся только needs_review.
2. **Дедуп по форме:** одна и та же порченая форма (одинаковый source_text + один entity_kind/
   контекст-класс) — ОДНА задача человеку; решение применяется ко всем вхождениям с провенансом.
   Если одна форма в разных контекстах даёт разные правильные варианты — НЕ схлопывать (разбить).
3. **Отсеять шум:** легит-формы (реальные рус.слова, единицы pCO2/CO2/ОФВ1, номера страниц,

4. **Сортировка: критические первыми** (icd/atc/tnm/доза/ген), затем термины.
5. **Кропы:** три уровня (слово ≥600 DPI / строка / страница с подсветкой bbox) — предгенерить.
6. **labeling_config.xml** + `tasks.json` в формате импорта Label Studio; кнопки: выбрать
   кандидата / свой вариант / «исходник верен» / «неразборчиво» / «нужен медэксперт».
7. **Доложить ТОЧНОЕ число:** сколько задач осталось человеку ВСЕГО и КРИТИЧЕСКИХ после

   размечать».
