# 16. Page router: выбор канала поверх неизменяемого IR

> **Редакция 2.** Модель `PageIR`, source inventory и ownership **перенесены в промпт 08** —
> вводить провенанс в самом конце значило бы переделывать его дважды. Здесь остаётся только
> то, ради чего промпт существует: **маршрутизация и выбор канала**. Также исправлены три
> ошибки первой редакции: `frozen=True` не даёт глубокой иммутабельности; одна строка
> `channel` не описывает страницу, где сработали native + font_repair + OCR-сверка; сумма
> каналов не равна числу страниц, если `table_model` — дополнительный канал.

К этому моменту уже есть: неизменяемый `PageIR` с `SourceSpan` и кандидатами по каналам (08),
недеструктивные таблицы с независимым reconcile (09), честный coverage (10), политики в
профиле (11), font-repair как канал класса A (13), gold set и метрики (14), решение по
challenger-компонентам (15).

Роутер — это то, что превращает разбросанные по `parser.py` и `ocr.py` цепочки `if` в
**явную, проверяемую, откалиброванную политику**.

```
Задача: ввести page-level router. Каждая страница получает канал по измеримому признаку,
а не по случайному порядку условий. Требует промптов 08-15.

=== ШАГ 1. Каналы страницы — не одна строка, а структура ===
Первая редакция писала `channel: str`. Этого не хватает: на странице с битым CID реально
работают native (база), font_repair (класс A) и OCR (сверка гомографов). Правильно:
    primary_channel: str            # чем получена основная масса selected-текста
    auxiliary_channels: tuple[...]  # какие каналы дали кандидатов / участвовали в сверке
Поля уже объявлены в `PageIR` (промпт 08). Здесь роутер их ЗАПОЛНЯЕТ.

`table_model` — **не канал страницы**, а обработчик региона. Он не участвует в подсчёте
`primary_channel` и учитывается отдельно (`table_regions: N`). Иначе сумма каналов
перестаёт равняться числу страниц — ошибка первой редакции.

=== ШАГ 2. Router (crparser/engine/router.py) ===
Правила — в `RoutingPolicy` профиля (промпт 11), НЕ в движке. Дефолт для КР:
  1. текстовый слой страницы пуст (< порога) -> `primary = ocr` (полный OCR);
  2. слой есть, сигнатур порчи нет -> `primary = native`. Дёшево и точно;
  3. слой есть, порча есть (§-токены, pseudo-ASCII, попадания пинов):
       - запустить font_repair (класс A). Если его confidence >= FONTREPAIR_MIN ->
         `primary = font_repair`, `auxiliary += ("native",)`;
       - если font_repair не справился (гомографы / шрифт не извлекается / класс B —
         пропавшие символы) -> `primary = ocr`, `auxiliary += ("native", "font_repair")`;
       - **расхождение font_repair и ocr на span'е -> `confidence: low` + запись в
         `provenance.disagreements`. Молча не выбирать никогда.**
  4. страница содержит таблицу -> регион обрабатывается табличным обработчиком
     (компонент из промпта 15; при исходе «никто не выигрывает» — текущий tables.py);
  5. exception-страницы (ни один канал не дал приемлемой уверенности) -> `vlm` ТОЛЬКО для
     adjudication, `source: vlm`, `confidence: low`.
     **VLM никогда не является неоспоримым источником.** Страница с `vlm` не может попасть
     в release без ручной проверки — жёсткое правило, проверяется в release.py (промпт 06).
Все пороги — именованные константы, откалиброванные на **gold-dev**, проверенные на
**holdout**. Не «на глаз».

=== ШАГ 3. Selected view не уничтожает источник ===
Роутер выбирает `selected` канал у каждого span'а. Он **не удаляет остальных кандидатов** —
они остаются в `SourceSpan.candidates`. Это инвариант из промпта 08, и роутер обязан его
соблюдать: любой выбор обратим, любое расхождение доказуемо.
Сегментер и табличный экстрактор читают **selected view** (плоский список Line), но
`PageIR` остаётся неизменным. Вычитание таблиц — маска span_uid для сегментера, а НЕ
физическое удаление текста. Именно мутация источника дала все потери из аудита.

=== ШАГ 4. Единый DocumentView (§1.5 аудита) ===
Сейчас PDF читается повторно: `batch_report.py` вызывает `parse_toc(pdf)`, который заново
открывает документ. На 57 681 странице это лишняя работа.
Фикс: `DocumentView` строится ОДИН раз (все `PageIR` + разобранное оглавление) и передаётся
и парсеру, и валидатору. PDF открывается один раз за прогон.

=== ШАГ 5. Диагностика маршрутизации ===
Аддитивно, в блок `provenance` (промпт 08):
    "routing": {
       "primary": {"native": 61, "font_repair": 12, "ocr": 3},   # СУММА == число страниц
       "auxiliary": {"native": 15, "font_repair": 3, "ocr": 12}, # может пересекаться
       "table_regions": 8,
       "vlm_pages": 0
    }
Замерить по всему корпусу и доложить: сколько страниц реально идёт по каждому каналу. Это
число, которого проекту не хватало с самого начала.

=== ГРАНИЦЫ ===
- Схема — аддитивно.
- Профиль КР не меняет доменную логику: он получает более чистый IR.
- Роутер НЕ УДАЛЯЕТ source evidence. Ни один канал не вправе выбросить исходный span;
  он может только предложить кандидата с указанием source и confidence.
- VLM не включать «на всякий случай». **Ноль страниц через VLM — нормальный и хороший исход.**

=== ТЕСТЫ-ПИНЫ ===
- Здоровый born-digital документ: 100% страниц `primary = native`; JSON байт-в-байт
  совпадает с результатом до роутера. **Роутер не меняет ничего там, где всё работало.**
- `routing.primary` суммируется РОВНО в число страниц документа. (`table_regions` в эту
  сумму не входит — ошибка первой редакции исправлена.)
- Иммутабельность: попытка мутировать `PageIR.spans`, `.candidates` или `.diagnostics`
  падает. Проверяется тестом, а не обещанием.
- КР1_4/КР628_2: страницы с битым CID идут по `font_repair`; `critical_span_exactness`
  (промпт 14) **растёт относительно baseline**. Улучшение доказано числом, не ощущением.
- Класс B (`стетогепатитный`, `ГЦРразвивается`) — чинится здесь, через OCR-канал, а не в 13.
  Проверить, что эти span'ы получили `primary = ocr` и восстановлены.
- PDF открывается ровно один раз за документ (счётчик/профайлер; сейчас — минимум дважды).
- Ни одна страница с `vlm` не попадает в candidate_release/ (проверяется release.py).
- **Полный gold-прогон: все метрики не хуже baseline, критические — лучше.** Любая
  просевшая метрика = регресс, разбираться ДО коммита.
- Throughput не хуже текущего более чем на 30%. Вдвое медленнее = что-то читается повторно.

=== РЕГЛАМЕНТ ===
1. Роутер вводится ЗА флагом (`--router`); старый путь остаётся рабочим, пока метрики не
   докажут превосходство.
2. Полный gold-замер: старый путь vs роутер. Публикуем ОБЕ колонки.
3. Только после этого роутер становится дефолтом; старый путь удаляется отдельным коммитом.
4. Коммит: «Page router: выбор канала по измеримому признаку поверх неизменяемого IR».

=== ПОСЛЕ ЭТОГО ПРОМПТА ===
Готовность корпуса считается честно: доля файлов, прошедших ОДИН замороженный
воспроизводимый прогон, независимый гейт, ручную проверку выборки и gold-пороги. Это ответ
на §6.4 аудита — тот процент, который сегодня равен нулю не потому, что данные плохи, а
потому, что их не на чем аттестовать.
```
