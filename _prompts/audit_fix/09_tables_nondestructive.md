## Почему reconcile должен быть независимым

Reconcile имеет смысл, только если сравниваются **два независимо полученных представления**
одной области:

| Источник | Что даёт | Кто считает |
|---|---|---|
| **A. Геометрия** | сетка ячеек: строки, колонки, границы | pdfplumber (`extract_table`) — собственная экстракция |
| **B. Источник** | `SourceSpan` внутри bbox с их текстом | наш IR (промпт 08), включая OCR/font-repair кандидаты |

`reconcile_score` = доля токенов из **B**, найденных в сетке **A**. Это осмысленная величина:
она падает, когда pdfplumber не смог разобрать структуру, когда таблица многостраничная и
обрезана, когда bbox захватил лишнее.

**Текст в итоговый `raw_text` берётся из B** (там восстановленный OCR/font-repair), а
**структура — из A**. Так мы одновременно чиним «битую таблицу при починенном теле» и
получаем честную метрику доверия.

=== ПРАВКА 3. Независимый reconcile ===
Для каждого кандидата:
  A = сетка ячеек от pdfplumber (`extract_table` на bbox) -> множество токенов;
  B = SourceSpan'ы, чей bbox лежит внутри bbox таблицы -> множество токенов
      (по SELECTED кандидату span'а, т.е. уже восстановленный текст).
  reconcile_score = |tokens(B) ∩ tokens(A)| / |tokens(B)|
  Нормализация токенов: casefold, без пунктуации, ё->е.
Пороги: RECONCILE_MIN = 0.80 для рамочных, RECONCILE_MIN_LOWCONF = 0.90 для безрамочных.

Вычитание (span_uids таблицы уходят из тела) — **только если score >= порога**.
Не прошло -> таблица ВСЁ РАВНО эмитится в `tables` (факт таблицы не теряем), но:
  - её span'ы НЕ идут в subtraction — текст остаётся в теле;
  - `reconciled: false`, `reconcile_score: 0.42`;
  - запись в warnings со страницей и score.
**Инвариант: `raw_text` пуст -> вычитания нет никогда, ни при каком score.**

=== ПРАВКА 4. Текст — из IR, структура — из геометрии ===
`raw_text` собирается из SourceSpan'ов внутри bbox в порядке чтения, разложенных по сетке
из A. pdfplumber — источник ГРАНИЦ ЯЧЕЕК, а не текста.

в таблице при живом `Barcelona Clinic Liver Cancer` в OCR-представлении тела.

=== ПРАВКА 6. Метрики полноты (отдельно от reconcile) ===

=== ДЕРЕВО РЕШЕНИЙ — идти по веткам САМОСТОЯТЕЛЬНО, не спрашивать ===

**Р1. Reconcile меряет СОХРАННОСТЬ, а не корректность.**
A (сетка pdfplumber) и B (IR-спаны) читают один нативный слой. Глиф-битая таблица даст
`score ≈ 1.0` — обе стороны видят одинаковый мусор (`ШСС`, `Т1а`, `МО`). **Это норма.**
Корректность — зона промпта 13. Записать это в комментарий к полю `reconcile_score`.
Тест «медиана ≠ 1.0» — **отменён**: два независимых экстрактора на чистой рамочной таблице
и должны сходиться на 100%. Проверять **левый хвост**, а не медиану.

**Р2. Reconcile слеп к усечённому bbox — нужен ВТОРОЙ сторож.**
Если детектор нашёл только шапку (КР628_2 Table 1: bbox ~118pt, 194 символа от
семистраничной таблицы), reconcile над этим крошечным bbox даст 1.0 и «успешно» вычтет.
Поэтому — независимая проверка ПОЛНОТЫ:
> таблица имеет подпись «Таблица N», но `row_count <= 1` → **warning `TABLE_STUB`**,
> НЕЗАВИСИМО от `reconcile_score`.

**Р3. КР628_2 Table 1 — три исхода, два допустимы:**
- (а) ансамбль нашёл строки препаратов → `row_count >= 9`, препараты в `raw_text` → **ОК, идти дальше**;
- (б) ансамбль не нашёл → `row_count = 1`, `TABLE_STUB` warning, **вычитания нет**, строки
  остаются в секции → **ТОЖЕ ОК, идти дальше**. Это валидный результат, не провал;
- (в) `reconciled=true`, `score=1.0`, `row_count=1`, ноль предупреждений → **ЗАПРЕЩЕНО**.
  Чинить Р2 и повторить.
