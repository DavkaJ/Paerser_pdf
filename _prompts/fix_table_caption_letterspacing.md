# Фикс: разрядка внутри подписи «Таблица N» ломает номер/заголовок таблицы

Проверено на корпусе (~230 файлов): класс НЕ единичный, сплошная разрядка подписи встречается ~10–15% файлов, реально теряют данные десятки. Уточнённый корень: регэксп в порядке (_clean_line схлопывает табы), но при СПЛОШНОЙ разрядке PyMuPDF (get_text("dict")) режет строку подписи на несколько визуальных Line, и до _collect_captions доходит огрызок. Три исхода одного класса: null/null (КР9_3), обрезанный caption (КР295_4), битый номер «1 0»→10 (КР459_2). Ложные срабатывания (законный null) отделены: «Критерии оценки качества» и безрамочные fallback low_confidence без «Таблица N» — НЕ трогать.

```
Баг: разрядка внутри подписи «Таблица N» ломает распознавание номера/заголовка таблицы.

Где: crparser/engine/tables.py — детектор подписей (_RE_TABLE_CAPTION, _collect_captions,
_norm_table_number, _match_caption). Больше НИЧЕГО не трогать.

Симптом. Когда строка подписи в PDF отрендерена сплошной разрядкой (лишние пробелы между
ВСЕМИ словами и внутри номера), PyMuPDF (page.get_text("dict")) дробит её на несколько
визуальных строк. До детектора доходит огрызок, подпись теряется полностью или частично.
Три исхода одного класса:

1. null/null (полная потеря). data/raw/КР9_3.pdf, стр.32:
     «Таблица     1   –   Антибактериальная     терапия     при     остром   неосложненном»
     «Таблица 2 – Антибактериальная терапия                 при     остром   неосложненном»
   В outout/КР9_3.json таблицы (page 32, bbox top 284.7 и 517.4) имеют number=null, caption=null,
   хотя таблицы детектированы (есть raw_text/bbox). Табл.3/4 на стр.33 (нормальный интервал) — ок.

2. Обрезанный caption. data/raw/КР295_4.pdf, стр.37:
     «Таблица     7.   Лекарственные      средства,    рекомендованные   для    купирования»
   В outout/КР295_4.json таблица (page 37): number="7", но caption="Таблица 7." — заголовок потерян.

3. Битый номер. data/raw/КР459_2.pdf: «Таблица      8.» разрядкой; и «Таблица 1 0.» →
   в outout/КР459_2.json caption="Таблица 1 0. Преимущества…", number захвачен как "1" вместо "10".

Диагноз (проверен). Регэксп _RE_TABLE_CAPTION в порядке (_clean_line в pdf_reader.py уже
схлопывает [ \t]+ → " ", и «Таблица 1 – …» матчится). Проблема: (а) при сплошной разрядке
подпись приходит РАЗБИТОЙ на несколько Line, и (б) разрядка внутри самого номера («1 0») не
нормализуется. Чинить сборку подписи в _collect_captions, а не регэксп.

Правильное поведение.
- Разряженная подпись распознаётся: «Таблица     1   –   Антибактериальная …» → number="1",
  caption собран из подписи и её переноса.
- Разрядка внутри номера схлопывается: «Таблица 1 0.» → number="10".
- Обрезанный заголовок восстанавливается: если строка-подпись матчит «Таблица N», но заголовок
  «оторван» в следующую(ие) визуальную строку(и), примыкающую по вертикали, — подклеить к caption.
- КР9_3 стр.32: обе таблицы получают number="1"/"2" и caption «Таблица 1 – Антибактериальная…» /
  «Таблица 2 – …».

ЯВНЫЕ ГРАНИЦЫ (жёстко).
- Править ТОЛЬКО детектор подписей в tables.py: _RE_TABLE_CAPTION, _collect_captions,
  _norm_table_number, _match_caption, при необходимости маленький локальный хелпер там же.
- НЕ трогать: детектор структуры разделов/заголовков, content-start, детекторы порчи (textnorm.py),
  validate.py, pdf_reader.py. Fallback безрамочных таблиц использует тот же _RE_TABLE_CAPTION —
  регэксп менять аккуратно, чтобы fallback не сломать.
- Склейку переноса заголовка делать ТОЛЬКО когда первая строка САМА матчит «Таблица N» И следующая
  строка примыкает по y (в пределах ~1.5 шага строки) И не является новой подписью/заголовком
  раздела/номером страницы. НЕ приклеивать подпись к чужой таблице, НЕ втягивать соседнюю прозу.
- Схлопывание разрядки в номере — ТОЛЬКО внутри уже захваченной группы номера (цифры+точки+запятые,
  разделённые пробелами), не по всей строке.
- НЕ превращать законный null у некапшенных таблиц в мусор: «Критерии оценки качества»
  (КР9_3 стр.23-24) и безрамочные fallback low_confidence без «Таблица N» в источнике ДОЛЖНЫ
  остаться number=null, caption=null.
- Без хардкода имён файлов/номеров/заголовков.
- Не расширять окно привязки в _match_caption (порог 120pt) — в этой задаче не решаем.

Тесты-пины (обязательны, до и после).
- КР9_3: таблицы стр.32 → number="1"/"2", caption начинается с «Таблица 1 – Антибактериальная…» /
  «Таблица 2 – Антибактериальная…»; таблицы стр.33 остаются number="3"/"4" (не регрессируют);
  таблица «Критерии оценки качества» (стр.23-24) ОСТАЁТСЯ number=null, caption=null.
- КР295_4: таблица стр.37 → caption содержит полный заголовок «Таблица 7. Лекарственные средства,
  рекомендованные для купирования мигренозного статуса» (а не обрезок «Таблица 7.»).
- КР459_2: подпись «Таблица 1 0.» → number="10".
- Регрессия (НЕ должны измениться): КР1019_1 («Таблица 1.2.2» — уже ОК), КР286_3 («Таблица 11» —
  уже ОК), КР1041_1 («Таблица 3» — уже ОК). number/caption прежние.

Регламент.
1. Полный регресс по всему корпусу.
2. Пересобрать outout/ и _corpus/report.json.
3. Интеграл-чек JSON (валидность; нет caption, приклеенных к чужим таблицам; число таблиц не упало).
4. Коммит ТОЛЬКО при нулевых регрессиях (кроме целевых улучшений в пинах).
5. Сообщение коммита — без упоминания Claude/AI/ассистента и без Co-Authored-By.
```
