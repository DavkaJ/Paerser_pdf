# Добить OCR тела: словарная дочистка двойников + дефис-склейка + сид терминов

Тестировать ТОЛЬКО на КР1_4, КР628_2 (+КР1000_1 регресс). Использовать существующий кэш OCR (crparser/data/ocr_cache). Весь корпус НЕ гонять.

## Корень «патчевого» тела (по коду, подтверждено)
Тело получает OCR-ленту, но замена почти не доходит:
1. Двойники тела (РБ-Ы→PD-L1, УЕСР→VEGF, СТЬА4→CTLA4, 8ТКШЕ→STRIDE, 1тВгах>е150→IMbrave150, уу/ух→vs) — ЧИСТАЯ кириллица без латиницы/§; `_is_broken_token` их не видит → чинятся только через doc_map.
2. doc_map покрывает тело неравномерно: короткие/строчные (уу/ух) статистикой не обучаются; hapax (8ТКШЕ, IMbrave150, одиночный УЕСР) не набирают поддержку.
3. Дефис-склейка: «анти-СТЬА4», «РБ-Ы-ингибитора» не матчатся — пин `стьа4→CTLA4` ЕСТЬ, но не применяется (`_hyphen_resolve` берёт только лидирующий компонент, двойник в хвосте/середине).

== КОРЕНЬ (подтверждён по коду) ==
Тело получает OCR-ленту (page-psm6 TSV закэширован), но замена до него почти не доходит:
1) Двойники тела — ЧИСТАЯ кириллица без латиницы/«§». _is_broken_token их не видит, поэтому
   _resolve_line/merge_line подставляют OCR-латиницу ТОЛЬКО через doc_map. Даже при верном band
   OCR-«PD-L1» на такой токен не ставится (ветка «нативный токен из слоя»).
2) doc_map покрывает тело неравномерно: _glyph_signal рубит короткие/строчные (уу/ух→vs нельзя
   обучить), hapax-термины тела не набирают поддержку (>=2 hits / gloss / base-value /
   value_support>=2): 8ТКШЕ, 1тВгах>е150, одиночный УЕСР не учатся.
3) Дефис-склейка с рус. морфемами («анти-СТЬА4», «РБ-Ы-ингибитора», «анти-УЕСР») не матчится ни
   _cyr_norm-ключом, ни _hyphen_resolve (тот заменяет лишь ЛИДИРУЮЩИЙ пробег). Из-за этого даже
   существующий пин "стьа4":"CTLA4" в теле не применяется.

== ЧТО СДЕЛАТЬ ==
А. РАВНОМЕРНО ПОКРЫТЬ КАЖДУЮ СТРОКУ ТЕЛА OCR+merge.
   - Для строк тела кандидата снимать OCR не только лентой (_band_text), но при необходимости
     построчным клипом по bbox (как для глоссария через _clip_text/psm7+апскейл), когда band
     пуст/съехал или в строке есть двойник — для надёжного соответствия слой↔OCR на плотных
     абзацах. Кэш клипов есть — использовать.
   - merge_line/_resolve_line НЕ ослаблять. Задача — не порог, а ПОКРЫТИЕ doc_map/пинов и дефис.

Б. СЛОВАРНАЯ ДОЧИСТКА ТЕЛА (главное).
   - Применять карту пинов (ocr_pins.json) СО ВСЕМИ известными кривыми вариантами термина как
     force-replace ПО ГРАНИЦЕ ТОКЕНА по всему тексту секций кандидата, включая тело. В пины
     добавить оба варианта PD-L1: "рбы"→"PD-L1" И "рэы"→"PD-L1"; "уеср"→"VEGF"; при подтверждении
     OCR — "8ткше"→"STRIDE", нормализованный вариант «1тВгах>е150»→"IMbrave150".
   - СИД доверенных чистых форм (по аналогии с base_values): PD-L1, PD-1, VEGF, VEGFR, CTLA4,
     HBsAg, HBs, TNM, BCLC, ECOG, RECIST, mRECIST, vs, mTOR, STRIDE, IMbrave150. Двойник, чью
     доминантную чистую форму OCR дал в теле и она входит в сид, принимать даже при ОДНОМ
     вхождении — это закрывает hapax тела.
   - ДЕФИС-СКЛЕЙКА: чинить сопоставление, когда двойник склеен с рус. морфемой через дефис в
     ХВОСТЕ/СЕРЕДИНЕ, а не только в начале. Заменять ПО ДЕФИС-ГРАНИЦЕ компоненты, чья кир-норма —
     полный ключ карты/пина, сохраняя русские компоненты. Не расширять до произвольной подстроки.
   - vs (уу/ух): чинить ТОЛЬКО пином — добавить нормализованные «уу»/«ух»/«уу.» → "vs"; статистику
     коротких двойников НЕ разблокировать (точечное исключение из _glyph_signal только для
     подтверждённых пинов).
   - УЧИТЬ ОБА ВАРИАНТА: если OCR дал пару «кривое→чистое» для формы из сида (и «рбы», и «рэы» →
     PD-L1), записывать ОБА кривых в new_map/шард и пополнять ocr_pins.
