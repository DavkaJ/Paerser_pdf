# Фикс: детектор порчи пропускает «обратную» глифовую порчу (кириллица → ASCII)

Проверено на живых данных: КР627_3 в report.json — FAIL, sections:0, corruption всё по нулям (порча не поймана). В теле PDF тотальная порча особого класса: кириллица отрендерена битым cmap в ASCII/псевдо-ASCII («1.2.1. (878>;>38O D>AD>@=>-:0;LF852>3> >1<5=0» = «Физиология фосфорно-кальциевого обмена»). Существующий детектор textnorm.py (_is_glyph_token / looks_glyph_corrupted) заточен под ОБРАТНЫЙ класс — латиница-отрендеренная-кириллицей (_CYR.fullmatch + биграммы), поэтому токены без кириллицы не ловит → needs_ocr=0 → файл падает в FAIL вместо REVIEW. Фикс безопасен при ПЛОТНОСТНОЙ (агрегатной) детекции, трогает только детектор порчи.

а не даёт им молча падать в FAIL. Классификация статуса — validate.py.
