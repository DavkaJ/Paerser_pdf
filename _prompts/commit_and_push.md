# Уборка рабочего дерева + коммит разрядочного фикса + пуш

```
Задача: привести рабочее дерево в порядок и запушить. Ничего из логики НЕ терять.
Действуй осторожно и с проверкой — при любой неоднозначности ОСТАНОВИСЬ и покажи diff,
а не сноси вслепую.

КОНТЕКСТ
- HEAD (ветка fix/heading-bleed-numbering-validator) уже содержит закоммиченные фиксы:
  обратная порча (textnorm/parser/pdf_reader/validate), глубокая вложенность (clinical.py),
  ведущий глиф перед номером (clinical.py), TOC-нормализация валидатора (toc.py/validate.py).
- В рабочем дереве ОДНА реальная незакоммиченная правка: crparser/engine/tables.py —
  распознавание подписи таблицы с разрядкой («Таблица   1 0» → номер «10», перенос заголовка).
- Остальной «шум» в рабочем дереве — это переводы строк CRLF: часть файлов пересохранилась с
  CRLF (например clinical.py: ~690 CR против 0 в HEAD), из-за чего git видит их «изменёнными»
  целиком, хотя логика не менялась. Проверено: git diff -w по segmenter.py/toc.py = 0.

ПОРЯДОК ДЕЙСТВИЙ
1. Отключи авто-CRLF на время уборки: `git config core.autocrlf false`.
2. Выведи ИСТИННЫЕ различия (игнорируя переводы строк):
   `git diff --ignore-cr-at-eol -w --stat HEAD`
3. Для КАЖДОГО модифицированного файла определи характер правки:
   - Если `git diff --ignore-cr-at-eol -w -- <файл>` ПУСТ → это чисто CRLF-шум, логика уже в HEAD:
     верни файл к HEAD: `git checkout -- <файл>`.
   - crparser/engine/tables.py → это целевой разрядочный фикс подписей: ОСТАВИТЬ.
   - Если у любого ДРУГОГО файла (textnorm.py/validate.py/parser.py/pdf_reader.py/clinical.py и т.д.)
     реальный (`--ignore-cr-at-eol -w`) diff НЕ пуст:
       * сверь его с уже закоммиченными фиксами. Если это ровно та же логика (артефакт
         пересохранения) — верни к HEAD (`git checkout -- <файл>`).
       * если это НЕЗНАКОМАЯ логика или УДАЛЕНИЕ рабочего кода (напр. пропала обработка
         метаданных «developer»/«year»/_extract_id в clinical.py) — ОСТАНОВИСЬ, распечатай
         этот diff и не коммить; сначала покажи, что нашёл.
4. ПРОВЕРКА целостности перед коммитом (обязательно):
   - `grep -c "developer" crparser/profiles/clinical.py` → должно быть > 0 (метаданные на месте).
   - Фиксы в HEAD не тронуты: `git diff --ignore-cr-at-eol -w HEAD -- crparser/engine/textnorm.py
     crparser/profiles/clinical.py crparser/engine/toc.py validate.py` → пусто (кроме, возможно,
     tables.py, который в стейдже).
   - Импорт-санити: `python -c "import crparser.engine.tables, crparser.profiles.clinical,
     crparser.engine.textnorm, crparser.engine.toc"` → без ошибок.
5. Стейдж и проверка стейджа:
   `git add crparser/engine/tables.py`
   `git diff --cached -w` → в стейдже ТОЛЬКО правки подписей таблиц (tables.py). Если попало
   что-то ещё — убрать из стейджа.
6. Коммит (по-русски, по существу, БЕЗ упоминания Claude/AI/ассистента, БЕЗ Co-Authored-By):
   `git commit -m "Распознавать подпись таблицы с разрядкой (Таблица N)"`
7. Защита от повторного CRLF-шума: создай файл .gitattributes с единственной строкой:
   `* text=auto eol=lf`
   затем `git add .gitattributes && git commit -m "Нормализовать переводы строк (LF)"`
8. Пуш текущей ветки:
   `git push origin HEAD`

КРИТЕРИЙ УСПЕХА
- `git status` чист (нет незакоммиченных изменений, кроме, возможно, игнорируемых outout/_corpus).
- Запушены ровно два коммита: разрядочный фикс подписей + .gitattributes.
- Никакая ранее закоммиченная логика не потеряна (проверки шага 4 прошли).
- Если на шаге 3/4 обнаружилось удаление рабочего кода или незнакомая правка — НЕ коммитить,
  вернуть файл к HEAD или сообщить, что найдено.
```
