# Проверить Tesseract и прогнать OCR-восстановление на кандидатах

OCR-модуль (crparser/engine/ocr.py) уже встроен, но на прошлом прогоне пропустился (нет `rus`
traineddata → graceful fallback). Нужно убедиться, что `rus`+`eng` доступны, и перегнать
файлы-кандидаты через OCR. Код НЕ менять — это операционный прогон.

```
Задача: активировать уже встроенное OCR-восстановление (crparser/engine/ocr.py) на
файлах-кандидатах. Проверить окружение, прогнать, отчитаться. Код не менять.

ШАГ 1. Проверка и, при необходимости, УСТАНОВКА Tesseract.
  Выполнить: tesseract --version ; tesseract --list-langs
  Требуется бинарь + traineddata И `rus`, И `eng`.
  Если бинаря нет или нет `rus` — УСТАНОВИТЬ автоматически (команды под текущую ОС):
    • Windows: `winget install --id UB-Mannheim.TesseractOCR -e` (или `choco install tesseract`).
      Затем проверить наличие rus.traineddata; если нет — скачать в папку tessdata
      (напр. rus.traineddata из github.com/tesseract-ocr/tessdata_best) и/или задать
      TESSDATA_PREFIX. Если бинарь не в PATH — задать TESSERACT_CMD (путь к tesseract.exe).
    • Linux (Debian/Ubuntu): `apt-get install -y tesseract-ocr tesseract-ocr-rus`
    • macOS: `brew install tesseract tesseract-lang`
  После установки повторить `tesseract --list-langs` и убедиться, что видны и `rus`, и `eng`.
  Только если установка НЕ удалась (нет прав администратора / нет сети) — ОСТАНОВИТЬСЯ и
  вывести точные ручные шаги (инсталлятор UB Mannheim с отметкой Russian, либо rus.traineddata
  в tessdata, + при необходимости TESSERACT_CMD/TESSDATA_PREFIX, которые ocr.py уже читает).
  OCR не прогонять, пока `rus`+`eng` не доступны.

ШАГ 2. Отобрать кандидатов из _corpus/report.json:
  - §-класс (гибрид): status==REVIEW с §-порчей (те, что §-детектор пометил);
  - тотальная порча: КР627_3, КР898_1;
  - сканы: класс SKIPPED_SCAN из scan_candidates.csv.
  (Имена не хардкодить — брать по статусу/классу/детектору.)

ШАГ 3. Перегенерировать ТОЛЬКО кандидатов через парсер (OCR активируется в ocr.py сам,
  раз rus доступен), атомарной записью в outout/. Чистые файлы не трогать.

ШАГ 4. Пере-валидация (validate.py) по перегенерированным + пересбор _corpus/report.json.

ШАГ 5. Отчёт (напечатать):
  - сколько кандидатов обработано; у скольких §-детектор стал 0 и статус сменился
    REVIEW→PASS; у скольких сканов/тотальной порчи sections стали непустыми;
  - список тех, кто НЕ восстановился (остался REVIEW) — с причиной, если видна.

ТЕСТЫ-ПИНЫ:
  - КР1_4: латиница восстановлена (HBsAg, Hepatitis B/C virus, anti-HCV, IgG/IgM,
    Child-Pugh, BCLC, TNM), «§»-мусор ушёл, §-детектор=0, статус PASS; кириллица и дерево
    разделов сохранены.
  - Один скан (SKIPPED_SCAN) + КР627_3, КР898_1: sections НЕ пустые.
  РЕГРЕССИЯ: чистые PASS (КР1000_1, КР802_1, КР845_1) не перегенерировались/не изменились.

РЕГЛАМЕНТ:
  - Интеграл-чек: все outout/*.json валидны.
  - Если это меняет код (не должно) — коммит только при нуле регрессий, без упоминания
    Claude/AI и без Co-Authored-By. Если только перегон данных — коммит не нужен (outout
    под .gitignore); просто отчитаться цифрами.
```
